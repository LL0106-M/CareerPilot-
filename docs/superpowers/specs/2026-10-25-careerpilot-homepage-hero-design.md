# CareerPilot 可滚动首页设计

日期：2026-10-25<br>
状态：讨论稿，等待确认<br>
关联文档：[CareerPilot 对话页设计](./2026-10-25-careerpilot-chat-page-design.md)<br>
范围：定义首页首屏、滚动转场、Dreaming 和底部产品介绍；不展开其他功能页的内部设计

## 1. 设计意图

首页首屏需要让用户在几秒内同时感受到两件事：CareerPilot 是一个长期陪伴者；它也能帮助用户把模糊困惑整理成可行动的下一步。

首屏不做任务仪表盘，也不承载完整聊天记录。它以泊泊为视觉主角，把品牌表达、职业困惑的可视化和一个轻量表达入口组织在同一场景中。用户既可以写下一句话进入独立对话页，也可以选择“只想先记下来”，把一个尚未成形的小想法保存到罗盘的想法视图。

## 2. 已确认方向

- 泊泊角色本身是首屏主视觉，不使用纯抽象罗盘替代角色。
- 泊泊会根据鼠标位置产生克制的视线与姿态反馈。
- 保留参考图中的三个元素：环绕罗盘的问题轨迹、职业探索意象、与泊泊相连的轻量对话入口。
- 对话入口与首屏场景融为一体，不再拆成下滑后的独立区块。
- 完整对话仍位于独立页面；首页只负责发起或继续对话。
- 首页提供“记个小想法”的快速捕捉状态，但不要求用户填写分类、方向、优先级或截止时间。
- 对话与小想法使用两块独立的磨砂玻璃：对话是主要入口，小想法是更轻的辅助便签。
- 小想法保存后进入 Idea Product State，并在罗盘的想法视图中呈现；它不会自动变成方向或航程任务。
- 顶部一级导航固定为：首页、对话、罗盘、航程、知识库。
- 顶部导航采用悬浮毛玻璃胶囊，而不是横跨全屏的实体栏。
- 视觉方向为温暖、成熟、克制的陪伴产品，减少手账拼贴感和儿童化装饰。

## 3. 页面结构

首屏占据一个完整桌面视口，采用不对称的双区构图。左侧完成叙事与交互，泊泊占据中央偏右的大幅空间；不再使用“左文案—中角色—右输入”的平均三栏：

```text
┌──────────────────────────────────────────────────────────────┐
│ CareerPilot     [ 首页  对话  罗盘  航程  知识库 ]      [用户] │
│                                                              │
│  You don't choose a future.          ○ 我适合什么？          │
│  You learn your way into one.    ○      ◇      ○             │
│                                                              │
│  Think aloud. Keep what matters.           泊泊               │
│  Take one small step.                   大幅动态角色            │
│                                                              │
│  [ 告诉泊泊你现在在想什么……                 → ]              │
│                                                              │
│      [ ✦ 记个小想法  刚刚想到什么？          ＋ ]              │
│                                                              │
│                         向下探索                              │
└──────────────────────────────────────────────────────────────┘
```

左侧不是一列普通表单，而是一段从品牌表达自然落到行动的叙事：英文主张 → 极短说明 → 对话玻璃 → 独立小想法便签。泊泊、罗盘和问题轨迹在中央偏右形成视觉重心。两区之间通过泊泊的视线和轨迹建立联系，不使用明显栏线。

## 4. 顶部导航

### 4.1 内容

- 左侧：CareerPilot 品牌标识，置于独立的小型磨砂玻璃表面，点击返回首页顶部。
- 中部：首页、对话、罗盘、航程、知识库，置于居中的悬浮毛玻璃胶囊。
- 右侧：通知入口和用户头像，使用独立的小型磨砂玻璃；未登录时可替换为“开始使用”。

### 4.2 交互

- 导航胶囊从首屏开始即使用温暖磨砂玻璃，让动态背景从后方透出。
- 当前栏目使用一块浅薄荷绿的半透明内层滑块；滑块随路由切换平滑移动，不整栏重绘。
- 页面下滑后，胶囊保持 sticky，并略微提高不透明度与模糊强度以保证可读性。
- 品牌、主导航和用户入口是三块独立悬浮表面，不用一条全宽背景把它们连起来。
- “对话”点击进入独立对话页，不在首页打开完整聊天窗口。

## 5. 左侧英文叙事

### 5.1 推荐文案

主标题：

> **You don’t choose a future.**<br>
> **You learn your way into one.**

辅助说明：

> Think aloud. Keep what matters. Take one small step.

主标题表达产品的核心观点：职业方向不是一次选择出来的答案，而是在表达、尝试和现实反馈中逐渐学习出来的。它必须比通用安慰句更具体地对应 CareerPilot 的产品闭环。

### 5.2 排版

- 主标题使用有编辑感的英文展示字体或高对比衬线体，但不得直接模仿参考图字体。
- 标题固定为两行，字号形成首屏第二视觉层级，仅低于泊泊。
- 辅助说明控制为一个短句，可按宽度断成两行；不再解释全部功能。
- 标题与辅助说明下方直接承接对话玻璃，中间不插入功能标签或按钮。
- 中文用户的实际输入提示继续使用中文，避免为了视觉统一增加理解门槛。

## 6. 中央泊泊与思考轨迹

### 6.1 角色呈现

- 泊泊占首屏视觉面积约 48%—56%，位于中央偏右，并允许部分轨迹延伸到左侧交互区上方。
- 保留毛绒材质、薄荷绿围巾、蓝色斜挎包和罗盘徽章。
- 角色不做夸张表情，默认状态是安静、关注、愿意倾听。
- 背景山景降低细节与饱和度，避免与角色竞争。

### 6.2 保留的问题轨迹

泊泊上方和右上方保留一条围绕罗盘展开的探索轨迹。首屏只出现三条问题：

- 我适合什么？
- 我真正喜欢什么？
- 下一步可以做什么？

罗盘、山峰、路径和问题属于同一组视觉，不再额外加入树叶、粗箭头、贴纸或大量手绘符号。轨迹使用低饱和琥珀色细线，默认透明度较低。

### 6.3 鼠标交互

鼠标移动时采用分层响应：

1. 泊泊眼睛跟随鼠标，视线变化是最主要反馈。
2. 头部相对鼠标方向产生不超过 4px 的轻微位移。
3. 围巾末端以约 120ms 延迟做小幅惯性摆动。
4. 鼠标靠近问题轨迹时，对应问题和连接线逐渐变清晰。
5. 鼠标靠近对话玻璃时，泊泊视线转向主输入框。
6. 鼠标靠近小想法便签时，泊泊视线略向左下移动，但动作幅度小于对话入口反馈。

动画不得持续跳动或主动吸引注意。鼠标停止后保留最后视线约 600ms，再缓慢回到默认状态。开启 `prefers-reduced-motion` 时只保留问题的透明度变化。

## 7. 左侧交互区

### 7.1 对话玻璃

对话入口紧接辅助说明下方，构图关系参考“标题—短说明—主输入”的产品展示方式，而不是放到页面另一侧：

```text
[ 告诉泊泊你现在在想什么……                         → ]
```

- 用户可以直接输入一条文本。
- 点击发送或按 Enter 后进入独立对话页，该文本成为新会话的第一条用户消息。
- 输入为空时，点击箭头直接进入对话页，不生成空消息。
- 返回首页时保留未发送草稿。
- 有历史会话时，在输入区下方显示弱文本入口“继续上次对话”，但不展示聊天记录。
- MVP 不在首页处理模式切换、附件上传、联网搜索或任务确认。

### 7.2 独立小想法便签

小想法不再与对话共用同一块玻璃，也不需要切换状态。它作为一块尺寸更小、透明度略高的独立磨砂便签，位于对话玻璃下方并轻微向右错位：

```text
✦ A THOUGHT WORTH KEEPING?
  不用想完整，先放在这里。
[ 刚刚想到什么？                         ＋ ]
```

捕捉规则：

- 用户只需输入原始想法，不需要标题、分类、关联方向、优先级或截止时间；
- Enter 保存，Shift+Enter 换行；空内容不能提交；
- 保存成功后显示“已放进罗盘”，并提供一个弱链接“去看看”；
- 泊泊不在此处生成回复，避免把快速记录变成一次完整对话；小想法也不会出现在对话历史中；
- 同一内容的重复点击通过 idempotency key 去重；
- 保存失败时保留原文并原地重试，不回退为假成功；
- 系统可以在后续 Dreaming 中发现它与某个方向的可能关联，但正式关联罗盘方向仍需用户确认；
- 小想法绝不自动转为航程任务。

### 7.3 保存动效

- 成功后，一枚低饱和琥珀色光点从输入区边缘沿罗盘轨迹移动约 `320–480ms`；
- 光点最终停在罗盘附近并淡出，表达“已经被收好”，不表达“已经被分析”；
- 小想法便签随后显示保存回执，用户可以继续记录；
- reduced-motion 模式下取消路径运动，只显示保存回执。

动效只能在真实接口保存成功后触发，不能在请求发出时提前播放。

### 7.4 后端契约

现有 `POST /v1/me/ideas` 可作为基础接口，但首页不要求用户填写 title。实现时允许 `title` 为空，由后端对 `raw_text` 做确定性截断生成展示标题；不为一次快速捕捉额外调用模型。

建议请求：

```json
{
  "raw_text": "也许我更喜欢能把复杂事情讲清楚的工作",
  "title": null,
  "authorization": "granted",
  "sensitivity": "normal",
  "related_goal_memory_id": null,
  "idempotency_key": "client-generated-key"
}
```

响应继续使用现有 Idea payload，初始阶段为 `captured`。首页不暴露 `captured / incubating / actionable` 等内部生命周期名称。

### 7.5 视觉

- 对话玻璃和小想法便签是两块独立材质面，不使用模式切换，也不做玻璃嵌套。
- 对话玻璃更宽、更稳定，使用稍高的不透明度与更清晰的输入对比；宽度建议为 `460–560px`。
- 小想法便签更窄、更轻，宽度建议为 `300–380px`，允许轻微位置错落，但不旋转或模拟手工贴纸。
- 两者均使用全站统一的温暖磨砂材质：暖白半透明表面、克制的背景模糊、1px 低对比边线和宽浅阴影。
- 发送按钮使用深松绿色圆形按钮，作为首屏唯一高强调控件。
- 小想法使用低强调加号，不与对话发送按钮竞争。

## 8. 视觉收敛原则

为提升成熟感，首屏遵循以下限制：

- 主色为暖白和深松绿，薄荷绿用于泊泊围巾，琥珀色只用于罗盘和关键光点。
- 除泊泊外，不再出现第二个大面积具象插画主体。
- 不使用玻璃卡片墙、数据指标、功能卡片和任务列表。
- 不使用大面积毛笔字、撕纸拼贴、飞舞树叶和多个手写箭头。
- 手写字体只允许出现在三个探索问题中，且字号和对比度低于主标题。
- 背景应提供空间感，不承担信息表达。

## 9. 响应式原则

### 桌面端

维持左侧叙事与交互、中央偏右泊泊的不对称构图。英文标题、对话玻璃和小想法便签保持一个视觉组；角色和轨迹根据视口宽度等比缩放。

### 平板端

英文标题缩小，泊泊移至右上安全区域；对话玻璃与小想法便签保持上下独立排列。品牌与用户入口保留，主导航胶囊可收进菜单，但保留“对话”快捷入口。

### 移动端

内容顺序调整为品牌与导航、英文标题、短说明、泊泊、对话玻璃、小想法便签。两块玻璃都使用全宽但保持独立间距。问题轨迹只保留一至两个问题；关闭鼠标跟随，替换为低频眨眼和呼吸动画。

## 10. 首页滚动叙事

首页不是多个独立模块的普通纵向拼接，而是一段由首屏自然进入 Dreaming、再由 Dreaming 收束到产品介绍的连续叙事：

```text
遇见泊泊并开始对话或记下想法
→ 用户表达成为一条可追溯线索
→ 多条线索在 Dreaming 中建立联系
→ 形成一条可纠正的观察
→ 产品介绍解释 CareerPilot 如何长期陪伴
```

### 10.1 页面节奏

| 阶段 | 建议高度 | 用户感知 | 主要变化 |
|---|---:|---|---|
| 首屏 | `100vh` | 遇见泊泊、开始对话或记下想法 | 泊泊跟随鼠标；表达入口可用 |
| 转场 | `140–180vh` | 进入泊泊的整理过程 | 首屏短暂固定；标题退出；线索沿罗盘轨迹移动 |
| Dreaming | `100–120vh` | 看见近期经历之间的新联系 | 线索汇聚；一条观察形成；用户可反馈 |
| 产品介绍 | 最少 `100vh` | 理解产品、技术与边界 | 信息列出现；山景展开；超大品牌字收束 |

### 10.2 首屏离场

滚动开始后的前 20%：

- 顶部导航从透明背景过渡为半透明暖白背景，并增加一条低对比分隔线；
- 左侧主标题向上移动并淡出；
- 表达入口完成对话输入后可以直接进入对话页；已保存小想法时先显示真实回执，未操作时则随首屏逐渐淡出；
- 泊泊停止跟随鼠标，视线转向上方罗盘；
- 背景山景产生低幅度视差，前景移动略快于远山。

### 10.3 线索转化

滚动进度约 20%–60%：

- 泊泊由中央缩小并移动到左下方，成为 Dreaming 场景中的观察者；
- “我适合什么”“我真正喜欢什么”“下一步可以做什么”三条探索问题逐渐散开；
- 三条问题分别转化为“你说过的”“你做过的”“你感受到的”三类线索；
- 只有当用户真实保存了小想法时，琥珀色光点才沿罗盘路径向上移动；未保存时不伪造个人线索；
- 背景由清晨暖白、淡金色缓慢过渡为安静的灰蓝和松绿色。

### 10.4 Dreaming 接管

滚动进度约 60%–100%：

- 首屏标题和输入入口完全退出；
- 罗盘成为中央视觉锚点；
- 三类线索围绕罗盘重新连接；
- `Dreaming` 标题、本次整理日期和观察结果逐渐出现；
- 滚动停止后停留在一个完整的 Dreaming 场景，不自动播放下一段。

### 10.5 动效边界

- 动效由滚动进度控制，用户停止滚动时画面同步停下，不使用强制自动播放。
- 首屏 sticky 转场不超过约 1.8 个视口，避免用户感到页面被锁住。
- 不使用大规模 3D、粒子系统或持续消耗性能的 WebGL 场景；优先使用分层素材、CSS transform、透明度和路径动画。
- `prefers-reduced-motion: reduce` 下取消 sticky 叙事，改为首屏与 Dreaming 的普通淡入淡出。

## 11. Dreaming 板块

### 11.1 产品意义

Dreaming 是 CareerPilot 对近期对话、行动和现实反馈进行去重、聚类和矛盾检查后的用户可见结果。它不是聊天摘要，也不是替用户生成的人格结论。

该板块需要让用户理解：

> 泊泊把我最近说过、做过和感受到的事情放在一起，发现了一条值得继续观察的联系。

### 11.2 方案选择

本轮采用 **轨道收束（Orbital Convergence）** 作为主视觉与交互方向。

曾考虑的方案：

- **航程回放**：因果关系清楚，但更像时间轴，适合“航程”页而不是首页高潮；
- **立体星图**：视觉冲击强，但文字可读性、移动端性能与 MVP 实现成本较差；
- **轨道收束（已选）**：能把“零散经历被整理成方向”本身变成动画，并延续首页已有的罗盘与航线语言。

这里的“高级感”来自留白、景深、克制的速度和精确的文字层级，不使用高饱和霓虹、密集粒子、强玻璃拟态或持续旋转的科技 HUD。

### 11.3 整体构图

Dreaming 是一段约 `110–130vh` 的沉浸场景。桌面端使用一张完整画面，不拆成三列卡片：

```text
┌──────────────────────────────────────────────────────────────────┐
│ DREAMING / 近期整理                                    10 月 25 日│
│                                                                  │
│  你说过的 ·──────╮                                               │
│                   ╲          ┌─────────┐                          │
│  你做过的 ·───────────◌──────│  罗 盘  │────── 新观察             │
│                   ╱          └─────────┘       清晰目标也许比      │
│  你感受到的 ·────╯                              “单位类型”更重要   │
│                                                                  │
│       泊泊                                         这是观察，不是结论│
│   注视正在形成的联系                          有点像  不太对  查看依据│
└──────────────────────────────────────────────────────────────────┘
```

- **左侧 28%**：三条尚未归位的线索，初始位置略有高低与远近差异；
- **中央 38%**：罗盘、三层椭圆轨道和唯一的视觉焦点；
- **右侧 34%**：最终观察、解释与反馈操作；
- **泊泊**：位于左下与中央之间，不抢占罗盘焦点，只通过视线、耳朵和呼吸响应整理进度。

画面背景从首屏的暖米白渐变到低饱和的灰蓝夜色，再在底部回到山谷晨光。不是突然切换成深色页面，而是像进入一层更安静的思考空间。

### 11.4 滚动驱动的五幕动画

Dreaming 使用一个 sticky 场景承载连续动画；页面滚动只控制进度，不把用户锁死在滚动捕捉中。

#### 第一幕：散落（0%–16%）

- 首屏的虚线航迹向下延伸，逐渐变细；
- 三个低对比光点从上一屏进入，停在画面左侧不同深度；
- `DREAMING / 近期整理` 以轻微上移和透明度变化出现；
- 泊泊已经在场，但只做缓慢呼吸，不主动表演。

用户第一眼看到的是“有些东西还没有被整理”，不是最终答案。

#### 第二幕：显影（16%–38%）

- 三个光点分别展开为“你说过的、你做过的、你感受到的”短句；
- 文字不是卡片：只使用一条细线、一个类型标签和最多两行原文；
- 三条线索按 `120–180ms` 的错峰依次显影；
- 背景产生非常轻的景深位移，鼠标移动最多影响 `6–10px`，不得造成眩晕。

#### 第三幕：入轨（38%–64%）

- 三条线索沿不同贝塞尔曲线靠近中央罗盘；
- 越接近中央，原文逐渐收为关键词，但原内容仍可通过 hover/focus 查看；
- 轨道只在节点经过时短暂亮起，避免无限循环的加载感；
- 罗盘不整圈旋转，只缓慢校正 `8–12°`，表达“找到相对方向”而不是“系统正在计算”。

#### 第四幕：形成（64%–84%）

- 三个节点在罗盘周围短暂停留，连接线先后出现；
- 中央产生一次柔和的呼吸光晕，不爆闪；
- 右侧观察文字按语义分两段出现：先出现关键判断，再出现限定语；
- 泊泊的视线从罗盘转向观察文字，告诉用户整理已经完成。

#### 第五幕：回应（84%–100%）

- 动画停止在可阅读状态，不继续漂移；
- 显示“这是观察，不是结论”以及三个操作；
- 用户继续向下滚动时，一条轨道延伸成细小航线，过渡到产品介绍的山谷光点。

所有关键内容必须在动画结束后稳定存在；动效不能迫使用户追着移动文字阅读。

### 11.5 三类线索与轨道编码

一次 Dreaming 在首页最多展示三条来源明确的线索：

| 线索 | 数据含义 | 轨道表现 | 示例 |
|---|---|---|---|
| 你说过的 | 对话中的用户原始表达 | 最外层、最慢、暖灰色 | “我不排斥产品工作，只是担心节奏太快。” |
| 你做过的 | 已完成、延期或取消的现实行动 | 中层、路径最明确、松石绿 | “比较了三个国央企数字化岗位。” |
| 你感受到的 | 行动反馈或阶段复盘中的感受 | 内层、轻微呼吸、雾蓝色 | “更喜欢目标清楚、能够独立推进的任务。” |

颜色只是辅助编码，类型标签和图形节点必须始终存在，不能仅靠颜色区分。

桌面端 hover、键盘 focus 或点击节点时，在节点附近展开来源浮层，包含：类型、日期、完整原文和“来自对话/航程反馈”的来源说明。首页不展示内部推理链，也不直接暴露数据库或模型字段。

### 11.6 新观察

首页一次只呈现一个当前最值得验证的观察，例如：

> 你在意的“稳定”，可能更接近清晰的目标和可预期的节奏，而不只是单位类型。

排版采用“大字号判断 + 小字号限定”的两段结构：

```text
你在意的“稳定”，
可能更接近清晰的目标和可预期的节奏。

而不只是单位类型。
```

观察下方固定出现：

> 这是泊泊根据近期经历形成的观察，不是对你的结论。

反馈操作：

- **有点像**：标记为 `resonates`，继续作为待验证候选，不自动晋升为稳定记忆；
- **不太对**：标记为 `not_quite`，降低后续使用权重；点击后在原位置展开三个轻量原因“理解偏了 / 已经变了 / 依据不够”，原因可跳过；
- **查看依据**：将三条轨道恢复为完整原文并固定展开，不跳转页面。

反馈成功后不弹 toast。按钮文字就地变为“收到，我会继续观察”或“收到，不按这个理解你”，罗盘光晕缓慢收束一次即可。

### 11.7 泊泊在 Dreaming 中的角色

泊泊不是洞察的装饰物，也不承担“施法生成答案”的角色：

- 散落阶段：坐在左下方看向线索；
- 入轨阶段：头部与视线以很小幅度跟随当前运动节点；
- 形成阶段：视线转向右侧观察；
- 用户反馈后：轻微点头或放松，不使用庆祝动画；
- 鼠标靠近泊泊时，只产生 `2–4px` 的视线跟随，不追逐光标。

角色存在的意义是让“系统整理”仍然像一次共同回看，而不是冷冰冰的数据分析。

### 11.8 视觉语言

- **底色**：`#F4F0E8 → #E9EEF0` 的大范围柔和渐变，保留纸张颗粒；
- **主文字**：接近墨绿黑的 `#24332D`，观察正文对比度优先；
- **轨道**：`rgba(89, 112, 103, 0.18)`，激活时不超过 `0.46`；
- **强调色**：松石绿与低饱和金，仅用于节点和一次性光晕；
- **字体层级**：英文 eyebrow 使用小号字距；观察使用较大的中文衬线或项目现有品牌标题字体；操作区继续使用无衬线；
- **材质**：允许极轻的纸张噪点和环境光，不增加大片毛玻璃卡片；
- **光效上限**：屏幕同时最多一个主光晕、三个节点微光，不出现满屏粒子。

### 11.9 前后端数据契约

当前后端已有 `/v1/me/daily-reviews`，但它只返回每日回顾；现有 hypothesis 与 snapshot 也没有一个可供前端安全消费的同批次聚合接口。首页不能在浏览器中把“最新回顾”“最新猜想”和“最新证据”自行拼接，否则可能把不同 Dreaming 运行的数据错误关联。

因此新增面向展示的只读接口：

```http
GET /v1/me/dreaming/latest
```

建议响应：

```json
{
  "run_id": "dreaming-job-id",
  "local_date": "2026-10-25",
  "status": "ready",
  "observation": {
    "id": "hypothesis-id",
    "statement": "你在意的稳定，可能更接近清晰的目标和可预期的节奏。",
    "confidence_band": "medium",
    "feedback": null
  },
  "evidence": [
    {
      "id": "event-id",
      "kind": "said",
      "excerpt": "我不排斥产品工作，只是担心节奏太快。",
      "occurred_at": "2026-10-24T21:18:00+08:00",
      "source_label": "对话"
    }
  ],
  "review": {
    "wins": ["比较了三个岗位"],
    "blockers": ["担心节奏不可控"],
    "tomorrow_step": "找一个从业者确认团队节奏"
  }
}
```

接口只返回该 observation 实际引用的 evidence，最多三条，并保证都来自同一个 `run_id`。若同类证据多条，由后端按相关性与时间选择；前端不进行语义筛选。

反馈接口：

```http
POST /v1/me/dreaming/observations/{observation_id}/feedback
```

```json
{
  "decision": "resonates",
  "reason": null,
  "expected_version": 1
}
```

`decision` 只接受 `resonates | not_quite`；`reason` 只在 `not_quite` 时可选。后端按 owner 隔离、做乐观锁和幂等处理，并返回更新后的 feedback 与 version。该反馈只更新候选观察的权重与状态，不直接改写长期记忆。

后端实现需要让 `career_hypotheses` 显式关联 `dreaming_job_id`，或建立独立的 Dreaming Read Model；不能依靠“创建时间最接近”进行关联。本 MVP 优先建立可重建的 Read Model，保留现有 Daily Review 数据结构。

#### Latest 选择规则

- 如果已有 `ready` 结果，同时新一轮仍在 `processing`：继续返回最近一条可用结果，并额外返回 `refresh_status: processing`；前端稳定展示旧观察，只在 eyebrow 附近提示“新的整理正在进行”；
- 如果新一轮失败，但存在旧结果：继续返回旧结果并返回 `refresh_status: failed`，不在首页主动打断用户；
- 如果从未形成可用结果且正在处理：返回 `status: processing`；
- 如果从未形成可用结果且材料不足：返回 `status: insufficient`；
- 不使用 `404` 表示“还没有 Dreaming”，`404` 只用于具体 observation 不存在或不属于当前 owner。

#### 本轮后端范围

本轮包含：首页 Dreaming Read Model、同一 run 的 evidence 关联、feedback 持久化、owner 隔离、版本冲突与 API 测试。本轮不包含定时 Dreaming 调度器、复杂权重学习和历史 Dreaming 管理界面。

### 11.10 前端组件边界

建议拆分为：

```text
HomeDreamingSection
├── DreamingHeader
├── OrbitalStage
│   ├── EvidenceNode × 3
│   ├── CompassCore
│   ├── OrbitPath × 3
│   └── BoboObserver
├── ObservationPanel
├── EvidenceDisclosure
└── DreamingEmptyState / DreamingErrorState
```

- 页面只请求一次 latest read model；
- 动画进度由 section 内的 scroll progress 驱动，数据请求与动画状态分离；
- SVG 负责轨道与连接线，HTML 负责所有文字，保证可选择、可缩放和可访问；
- Framer Motion 负责节点路径、透明度和低幅度视差；不引入 WebGL 或新的动画引擎；
- 用户反馈使用 optimistic UI，但失败时恢复原按钮并在操作区内显示重试。

#### 页面与路由决策

- 新的可滚动首页使用正式路由 `/`；
- 旧 `/today` 重定向到 `/`，不再保留第二套首页；
- `/dreaming`、`/memory` 暂时保留以兼容已有功能和测试，但不出现在新版顶部主导航；
- 顶部导航固定为：首页、对话、罗盘、航程、知识库；
- 首页小对话框真实调用 `/v1/chat`，成功后携带后端返回的 `conversation_id` 进入 `/chat`；
- 对话页在本轮只补齐“接管首页首条真实会话”的最小能力，不重做完整对话页视觉；
- 首页发送失败时保留输入内容并原地重试，不提前跳转，也不回退成模拟回答。

### 11.11 状态设计

#### 加载中

保留场景高度和罗盘轮廓，只显示静态的三个灰色节点；不播放完整收束动画，避免数据返回后从头跳动。

#### 材料不足

不生成模拟洞察。中央显示三枚尚未连接的光点，文案为：

> 和泊泊聊过、尝试过一些事情以后，这里会慢慢出现属于你的线索。

唯一动作“去和泊泊聊聊”进入独立对话页。

#### 正在整理

若后端返回 `processing`，文案为“泊泊正在把最近的片段放到一起”。轨道做一次极慢的呼吸，不使用无限旋转 loading。

#### 请求失败

展示静态场景与“这次整理暂时没有取回来”，提供“重新加载”。不退回伪造 demo 数据。

#### 已反馈

刷新页面后保持反馈状态；按钮不可重复提交，但允许通过“重新考虑”恢复为未反馈状态，这一能力可延后到独立 Dreaming 页面，首页 MVP 不提供。

### 11.12 响应式与可访问性

- `>= 1100px`：完整横向轨道收束；
- `720–1099px`：罗盘居中，线索围绕上半部，观察位于下半部；
- `< 720px`：取消复杂路径跟随，改为三条线索随纵向滚动依次靠近罗盘，观察在罗盘下方出现；
- `prefers-reduced-motion: reduce`：直接展示整理完成的稳定画面，仅保留 opacity 过渡；
- 所有节点可通过 Tab 聚焦，Enter/Space 展开依据；
- SVG 轨道设为 `aria-hidden`，真实语义由 HTML 列表表达；
- 观察与操作必须达到 WCAG AA 对比度，不能把低对比当成高级感。

### 11.13 性能边界

- 不使用 WebGL、Canvas 粒子系统和实时模糊滤镜；
- 动画只改变 `transform`、`opacity` 和 SVG path progress；
- 同屏运动节点不超过三个，环境装饰点不超过五个；
- 鼠标视差在 `requestAnimationFrame` 中合并更新；
- 首屏资源加载完成前不预载大尺寸 Dreaming 动画素材；
- 中低端设备或掉帧时自动关闭景深视差，保留主收束动画。

### 11.14 Dreaming 到产品介绍的转场

观察形成后，一条轨道从罗盘向下延伸。继续滚动时，它逐渐变成山谷中的细小光点，并进入底部产品介绍的山景。产品介绍随后解释用户刚刚体验到的闭环：

```text
表达 → 整理 → 看见方向 → 现实验证 → 再次整理
```

### 11.15 Dreaming 验收标准

- 用户不阅读说明也能看出三条零散线索正在汇聚成一个观察；
- 用户能区分“原始依据”和“系统观察”，且观察明确标注不是结论；
- observation 与 evidence 必须来自同一个 Dreaming run；
- “有点像 / 不太对”反馈刷新后仍然存在，且不会直接改写长期记忆；
- 桌面端滚动动画流畅，移动端与 reduced-motion 模式可完整阅读和操作；
- 材料不足、处理中和接口失败时都不显示伪造洞察；
- 动态效果停止后，所有文字保持稳定且可选择。

- Dreaming 线索不足时使用明确空状态，不展示演示数据冒充用户数据。
- 外部技术链接不可用时不影响页面主体；链接在新标签页打开并标明外部跳转。
- 首屏角色动态素材尚未加载时显示静态泊泊图，不显示空白占位。

## 14. 完整首页验收标准

- 用户在首屏 5 秒内能理解产品同时提供陪伴和行动帮助。
- 首屏只有一个高强调行动：发送内容并进入对话；“只想先记一下”作为低强调辅助入口。
- 用户可以不进行分类和自我分析，直接保存一个小想法。
- 小想法保存成功后出现在罗盘的想法视图，不自动变成职业方向或航程任务。
- 对话草稿与小想法草稿在本地分别保存，切换状态时不会互相覆盖。
- 泊泊是首屏最强视觉焦点，英文主张与对话入口共同构成第二视觉层级，小想法便签保持低强调。
- 顶部导航完整显示：首页、对话、罗盘、航程、知识库，并使用居中的悬浮毛玻璃胶囊。
- 对话玻璃和小想法便签彼此独立，不通过模式切换共用同一输入表面。
- 参考图中的问题轨迹、罗盘和轻量对话入口得到保留。
- 首页不呈现任务仪表盘或完整聊天记录。
- 首屏、Dreaming 和产品介绍之间形成连续视觉叙事，不出现生硬模块切换。
- Dreaming 始终展示来源、候选性质和用户纠正入口。
- Dreaming 空状态不伪造个人洞察。
- 底部产品介绍包含英文定位、GitHub、Menu、Essentials 和 Technology & Research。
- `Essentials` 仅包含 Privacy 与 Safety。
- `Technology & Research` 使用单层平铺列表，不暗示所有项目都是合作或赞助方。
- 所有关键动效均提供减少动态效果的降级方案。

## 15. 本轮不包含

- 对话、罗盘、航程、知识库页面的内部结构；
- 泊泊眼球、头部和围巾动画素材的具体制作方式；
- Dreaming 后台任务、Memory Patch 和数据模型的技术实现；
- 后端会话创建、草稿保存和鉴权接口设计；
- Privacy、Safety 独立页面的正文；
- Technology & Research 外部项目关系的法律或品牌授权说明。
