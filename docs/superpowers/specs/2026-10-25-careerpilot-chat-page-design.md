# CareerPilot 对话页设计

日期：2026-10-25<br>
状态：讨论稿，待统一前端设计时合并<br>
关联文档：[CareerPilot 可滚动首页设计](./2026-10-25-careerpilot-homepage-hero-design.md)

## 1. 页面定位

对话页是用户与泊泊持续交流的主要空间。它不是 Agent 控制台，也不是把罗盘、航程和知识库压缩进同一个仪表盘。

用户进入页面后应当只需要做一件事：直接说话。Agent 在后台判断当前更适合倾听、梳理、探索还是行动；当对话产生可以沉淀到其他页面的内容时，再通过右侧情境抽屉呈现关联结果。

核心体验：

> 像在一个安静、有生命感的空间里和泊泊持续交谈；需要工具时，工具自然出现，但不会接管对话。

## 2. 已确定的设计决策

- 页面使用同一套温暖、缓慢动态的山谷背景；MVP 不随支持模式切换天气或场景。
- 全站采用温暖磨砂玻璃材质，对话页是该材质系统的核心示例。
- 左侧只管理历史对话和对话文件夹，不管理上传文件。
- 中间是唯一的主对话空间。
- 右侧使用可收起的情境抽屉，承载与罗盘、航程、知识库的关联结果。
- 四种支持模式由 Agent 自动判断，不在前端显示模式选择器，也不要求用户调整。
- 用户可以上传 PDF、DOCX、TXT 和 Markdown；图片、Excel、PPT、音视频不在首版范围。
- 临时附件默认只服务当前对话；只有用户确认后才保存到个人知识库。
- Dreaming 线索自动收集，不要求逐条确认；它们不会直接变成稳定结论或长期记忆。
- 写入罗盘、航程、知识库和高影响长期记忆前必须由用户确认；用户明确说“请记住”的普通信息沿用现有保守写入策略，并提供可撤销回执。
- 待确认关联不会自动打开右侧抽屉，只用柔和光点和数量提醒用户。

## 3. 目标、非目标与反目标

### 3.1 目标

- 用户打开页面即可开始自然对话，不需要理解系统模式和工具路由。
- 首页发送的第一句话可以无缝进入对话页继续。
- 对话、附件、引用和其他页面的关联关系清晰可追溯。
- 页面同时具有陪伴感和实用性，但对话始终是视觉主角。
- 左右栏均可收起，在宽屏、中屏和移动端保持可用。
- 后端真实保存会话、文件状态和关联确认，不使用前端假数据伪装成功。

### 3.2 非目标

- 不在本轮重做罗盘、航程和知识库页面内部结构。
- 不支持图片理解、表格工作簿分析、PPT、音视频或代码执行。
- 不展示模型推理链、系统 Prompt、Memory 检索分数或内部工具参数。
- 不把聊天页做成项目管理看板。

### 3.3 反目标

即使功能可用，出现以下情况也视为设计失败：

- 用户需要先选择“倾听 / 梳理 / 探索 / 行动”才能发送消息；
- 右侧长期显示检索范围、联网状态等后台术语；
- 页面同时出现大量毛玻璃小卡片，形成“玻璃套玻璃”；
- 动态背景持续抢夺文字注意力或影响滚动与输入性能；
- Agent 未经确认就创建行动、修改罗盘或永久保存附件；
- 上传文件进入长期记忆，或删除后仍能被检索。

## 4. 考虑过的页面结构

### 4.1 固定双栏

聊天区和工具区始终同时显示。信息效率高，但空工具区会长期占据空间，整体更像工作台，陪伴感较弱。

### 4.2 悬浮工具画布

工具结果以大浮层覆盖对话。视觉冲击强，但频繁打开会遮挡上下文，不适合作为默认结果载体。

### 4.3 情境抽屉（已选）

右侧默认收为窄边；产生岗位、方向、行动或文件结果时，只显示提示光点和数量。用户点击后展开抽屉，查看和确认关联。

采用原因：保持对话纯粹，同时给工具结果一个稳定、可追溯的位置；复杂内容仍能从抽屉进入对应独立页面。

## 5. 桌面端整体架构

```text
┌────────────────────── 顶部全局导航 ──────────────────────┐
│ CareerPilot        首页  对话  罗盘  航程  知识库          │
├──────────────┬───────────────────────────┬────────────────┤
│ 历史对话栏    │ 当前对话空间               │ 情境抽屉        │
│ 260px / 52px │ 自适应，主要视觉区域          │ 48px / 420px   │
│              │                           │                │
│ 新建 / 搜索   │ 泊泊与消息                  │ 待确认关联      │
│ 文件夹        │ 引用与附件                  │ 岗位 / 方向     │
│ 最近对话      │                           │ 行动 / 文件     │
│ 已归档        │ 底部输入玻璃                │                │
└──────────────┴───────────────────────────┴────────────────┘
```

三块区域位于同一个动态环境中，不使用三张完全封闭的白色卡片。视觉主次顺序为：当前对话 > 左侧历史 > 右侧工具。

## 6. 页面进入与构图变化

### 6.1 新对话初始状态

- 动态山谷占据整个工作空间；
- 中央偏下悬浮一块宽大的温暖磨砂输入玻璃；
- 泊泊坐在玻璃左侧边缘，保持轻微呼吸；
- 问候文案为“我在。你想从哪里说起？”；
- 输入区提供附件、历史和发送能力，不展示 Prompt 商店或模式选择；
- 右侧情境抽屉收起，左侧历史栏保持用户上次选择的展开状态。

### 6.2 第一条消息发出后

- 输入玻璃在 `280–360ms` 内缓慢下移并固定到内容区底部；
- 上方释放为消息阅读区；
- 泊泊从输入框边缘移动到第一条回复附近；
- 后续消息进入稳定对话布局，不重复播放入场大动画；
- 从首页带入首条消息时，直接从该过渡开始，不重复展示空白欢迎态。

### 6.3 返回已有对话

直接恢复历史消息与滚动位置。输入框固定在底部，不播放新对话入场动画；动态背景从低运动状态淡入。

## 7. 温暖磨砂玻璃系统

### 7.1 材质层级

| 层级 | 使用位置 | 视觉特征 |
|---|---|---|
| 环境层 | 动态山谷背景 | 无玻璃，低对比、低饱和、有纵深 |
| 导航层 | 顶部导航 | 稳定强磨砂，最高文字清晰度 |
| 工作层 | 对话阅读区、输入区 | 暖白轻磨砂，大面积、少边框 |
| 浮动层 | 左栏菜单、右侧抽屉、附件预览、确认框 | 更强模糊与顶部高光，明确前后层级 |

### 7.2 推荐视觉参数

- 暖白底色透明度约 `72%–82%`；
- 背景模糊 `28–36px`，移动端降为 `16–22px`；
- 边框为低透明暖白，仅顶部保留极细高光；
- 阴影宽而浅，不使用黑色硬阴影；
- 允许极淡纸张噪点；
- 主体分组优先依靠留白和排版，不持续嵌套玻璃卡片。

具体参数最终进入全局 design tokens，所有页面复用，不在各页面自行定义相近颜色。

## 8. 动态背景

MVP 使用同一套分层山谷场景，不使用循环视频：

- 远山以极慢速度产生横向视差；
- 山腰薄雾缓慢移动；
- 路径上偶尔出现向远处移动的微弱光点；
- 鼠标移动只影响 `4–8px` 景深；
- 泊泊进入思考状态时，环境亮度只做极轻变化；
- 页面空闲后运动幅度自动减弱；
- `prefers-reduced-motion` 下显示静态山谷；
- 背景不随“倾听 / 梳理 / 探索 / 行动”改变天气或颜色。

不使用 WebGL、实时粒子系统和大面积持续模糊动画。背景运动层优先使用 transform 与 opacity，避免影响输入延迟。

## 9. 中央对话空间

### 9.1 消息表现

- 不使用密集、等尺寸的客服式气泡；
- 用户消息靠右，以低饱和松石绿或暖灰绿轻底色表达；
- 泊泊回复靠左，使用更开放的书信式排版，可带小型泊泊状态；
- 连续的泊泊回复合并头像和称呼，减少视觉噪音；
- 长回复使用明确段落、列表和引用，不默认折叠正文；
- 外部事实引用在相关句子后显示小型来源标记，点击后在右侧抽屉查看来源；
- 内部工具状态不作为聊天消息插入。

### 9.2 Agent 状态

四种支持模式完全由后端判断，前端不显示切换器。用户只感知自然语言和泊泊的轻微状态：

- 等待回复：呼吸减慢；
- 思考：眼神或罗盘产生一次轻微运动；
- 调用资料：回复区显示“泊泊正在查看你允许使用的资料”；
- 生成外部行动预览：右侧关联栏亮起，但不会自行执行。

状态文案面向用户描述正在发生的事情，不显示 `retrieval`, `memory_write` 等系统字段。

### 9.3 输入区

输入区固定在当前对话区域底部，是一整块温暖磨砂玻璃：

- 多行文本输入，随内容增长到最大高度后内部滚动；
- Enter 发送，Shift+Enter 换行；
- 回形针上传附件；
- 发送按钮在无内容且无附件时禁用；
- 请求进行中允许继续输入下一条草稿，但不重复提交当前消息；
- 网络失败时保留原文和附件，可原地重试。

不放语音、Prompt 模板、模型选择和支持模式切换，除非后续独立需求明确加入。

## 10. 左侧历史对话栏

左栏只整理对话，不管理文件。

### 10.1 展开状态

- 顶部：新建对话、搜索；
- 中部：用户创建的文件夹，可重命名、折叠和拖入对话；
- 文件夹下：对话标题与最后更新时间；
- 未归类区域：最近对话；
- 底部：已归档和收起按钮；
- hover/focus 时才显示重命名、移动和归档操作；
- 删除放在二级菜单中并二次确认，不与归档并列为首要操作。

### 10.2 收起状态

- 宽度约 `52px`；
- 只保留新对话、搜索和展开图标；
- 不用纯图标表达高风险操作；
- 收起状态持久化到本地偏好。

### 10.3 文件夹边界

文件夹只包含 conversation，不包含附件、知识库文件、罗盘项目或航程任务。对话内附件仍通过该对话可追溯；永久文件统一在知识库管理。

## 11. 右侧情境抽屉

### 11.1 默认状态

抽屉收起为约 `48px` 的窄边，只显示一个关联入口。产生新的待确认内容时：

- 出现一个柔和光点；
- 显示待确认数量；
- 不自动展开；
- 不播放声音或强提示动画。

### 11.2 展开结构

面板标题为“本轮关联”，内容按产生顺序展示，不使用复杂多级 Tab：

- **罗盘**：方向观察、约束或待验证猜想；
- **航程**：下一步行动、提醒或外部操作预览；
- **知识库**：岗位结果、资料引用和附件保存；
- **本轮依据**：回复真正使用的公开来源与私人资料片段。

每项只显示摘要、来源和一个明确主动作；需要复杂编辑时进入对应页面完成。

### 11.3 关联确认规则

| 内容 | 是否确认 | 行为 |
|---|---|---|
| Dreaming 线索 | 否 | 自动进入待整理材料，不改写长期结论 |
| 罗盘观察 / 猜想 | 是 | 用户确认后写入候选状态 |
| 航程行动 | 是 | 用户确认后创建；外部写操作仍需 Preview → Confirm → Apply |
| 当前对话临时附件 | 否 | 只用于当前对话 |
| 附件保存到个人知识库 | 是 | 建立 owner 隔离的私有索引 |
| 高影响长期记忆 | 是 | 继续走记忆确认与版本规则 |

“高影响”在本轮明确指：Agent 推断出的稳定偏好或长期目标、敏感信息、与已有有效记忆冲突的更新，以及会替换或停用已有记忆的变更。用户明确要求“请记住”的普通、非敏感信息不额外弹窗，但回复下方必须显示可撤销的保存回执。

Dreaming 自动收集不弹窗。若需要透明度，只在相关回复下显示不可交互的小字“已留作后续整理的线索”。

### 11.4 确认反馈

- 确认成功后就地变为“已加入罗盘 / 已加入航程 / 已保存到知识库”；
- 不使用全局 toast 作为唯一反馈；
- 失败时保留预览和用户输入，提供原地重试；
- 关联完成后提供“打开对应页面”，但不自动跳转。

## 12. 文件上传与引用

### 12.1 支持范围

首版支持：PDF、DOCX、TXT、Markdown。

不支持图片理解、Excel、PPT、音视频和压缩包。前端文件选择器和后端校验必须使用同一白名单，不虚假显示尚未支持的格式。

### 12.2 上传流程

```text
选择文件 → 校验名称/大小/格式 → 上传中 → 解析中
→ 当前对话可使用 → 用户可选“保存到个人资料库”
```

状态：`uploading | parsing | ready | failed | deleted`。

### 12.3 隐私边界

- 临时附件与当前 conversation 绑定；
- 未确认保存时，不出现在个人知识库；
- 文件正文不自动进入长期记忆；
- 对话引用文件时显示文件名和片段；
- 删除附件后立即停止后续检索，并清理派生索引；
- 保存到知识库后仍只允许当前 owner 检索。

## 13. 对话历史与后端契约

当前后端已有 `/v1/chat` 和 owner cookie，但前端仍使用模拟回复，也缺少对话历史、文件夹、附件上传和面向前端的流式传输接口。本页落地需要补齐以下契约。

### 13.1 会话与文件夹

```http
POST   /v1/me/conversations
GET    /v1/me/conversations
GET    /v1/me/conversations/{conversation_id}/messages
PATCH  /v1/me/conversations/{conversation_id}
POST   /v1/me/conversation-folders
PATCH  /v1/me/conversation-folders/{folder_id}
DELETE /v1/me/conversation-folders/{folder_id}
```

conversation 更新支持标题、folder_id 和 archived；文件夹删除时默认将内部对话移回“未归类”，不得连带删除对话。

### 13.2 发送消息

保留现有 `/v1/chat` 的语义，并增加附件引用。为获得正常大模型对话体验，新增 SSE 流式端点或等价的 run event stream：

```http
POST /v1/chat/stream
```

请求至少包含：

```json
{
  "conversation_id": "conversation-id",
  "message": "请结合这份 JD 看看我适不适合",
  "attachment_ids": ["attachment-id"]
}
```

`support_mode` 继续允许后端内部使用，但前端默认不传，由 SupportPolicy 自动判断。

流事件只暴露稳定的用户可见事件，如 `message.delta`、`citation.ready`、`artifact.ready`、`run.completed` 和 `run.failed`。不得把模型内部思维链作为事件发送到浏览器。

### 13.3 附件

```http
POST   /v1/me/conversations/{conversation_id}/attachments
GET    /v1/me/conversations/{conversation_id}/attachments
GET    /v1/me/attachments/{attachment_id}/status
DELETE /v1/me/attachments/{attachment_id}
POST   /v1/me/attachments/{attachment_id}/save-to-knowledge
```

上传使用 multipart，返回稳定 attachment_id；解析可以异步完成。聊天只能引用属于当前 owner 且状态为 ready 的附件。

### 13.4 页面关联结果

后端把可沉淀结果作为结构化 artifact 返回，而不是让前端从回复文本中再次抽取：

```json
{
  "artifact_id": "artifact-id",
  "kind": "compass_hypothesis",
  "summary": "你可能更看重目标清晰，而不仅是单位类型",
  "target": "compass",
  "confirmation_required": true,
  "status": "proposed"
}
```

```http
GET  /v1/me/conversations/{conversation_id}/artifacts
POST /v1/me/conversation-artifacts/{artifact_id}/confirm
POST /v1/me/conversation-artifacts/{artifact_id}/dismiss
```

确认接口必须校验 owner、版本和目标类型。Dreaming evidence 不进入待确认 artifact 列表，由后端按既定策略自动收集。

MVP 的可确认 artifact 只包含以下四类：

| kind | 确认后的真实写入 |
|---|---|
| `compass_hypothesis` | 创建一条带依据的候选假设，不直接变成确认事实 |
| `journey_task` | 创建一条“准备开始”的航程任务，不自动执行外部操作 |
| `knowledge_save` | 将 conversation attachment 提升为个人知识库资料并建立私有索引 |
| `memory_candidate` | 确认一条高影响 Memory candidate，继续遵循版本和冲突规则 |

岗位结果与引用只读展示，不属于 artifact；飞书、日历、WPS 等外部动作继续使用现有 `Preview → Confirm → Apply → Verify` 流程，不折叠为一次通用 artifact 确认。

### 13.5 用户可见消息存储

现有 Harness session log 是内部运行记录，不能直接作为产品聊天历史。新增 owner 隔离的 conversation/message read model：

- 用户消息在开始模型运行前持久化；
- assistant message 支持 `streaming | completed | cancelled | failed`；
- 取消时保留已经出现的部分文本并标记“已停止”；
- 失败时保留部分文本和失败状态，但该部分文本不进入后续 Agent 上下文；
- 重试创建新的 run 和 assistant attempt，并关联同一条 user message；
- 每次发送和重试都携带 client idempotency key，避免刷新或网络重放产生重复消息。

### 13.6 持久引用快照

每条 assistant message 持久化它实际使用的来源快照，至少包含：来源类型、标题、URL 或私有文档 ID、当时使用的 excerpt、发生时间和 citation_id。

- 公共来源保留标题、URL 与当时引用片段；
- 私人附件或知识库资料删除后，历史消息仍保留“曾使用某个已删除资料”的占位关系，但必须清除可检索正文与 excerpt；
- 重新打开旧对话时不依赖重新运行 RAG 来还原当时引用；
- 引用快照只用于解释当时回复，不自动进入长期记忆或公共知识库。

### 13.7 首页首条消息交接

首页不把草稿放在 URL 或仅存在浏览器内存中。它调用：

```http
POST /v1/me/conversations
```

并提交 `initial_message` 与 `idempotency_key`。后端在同一逻辑事务中创建 conversation、持久化首条 user message 并启动 run，返回 `conversation_id` 与 `run_id`；前端随后进入 `/chat/{conversation_id}` 并继续订阅流事件。创建失败时留在首页并保留原输入。

该协议保证刷新、回退和重复点击不会生成两段相同对话。

### 13.8 引导页一致性

现有 IntroPage 中强制选择“先听我说 / 帮我梳理 / 一起探索 / 帮我行动”的步骤与本设计冲突，应在本轮移除。首次进入只收集真正必要的信息；支持模式始终由 Agent 根据当前消息判断。

### 13.9 对话删除与级联

本轮保留归档与删除两个不同动作：

- 归档只改变可见分组，不删除消息、附件或关联；
- 删除需要二次确认，立即从正常查询与 Agent 上下文中隐藏；
- 后端建立删除 tombstone 并级联清理消息、未保存临时附件、派生索引、引用正文和未确认 artifact；
- 已提升到个人知识库的资料不随对话删除；只移除该对话的引用关系；
- 已确认写入罗盘、航程或记忆的内容保留，但其来源显示为“原对话已删除”，不保留被删除的原文；
- 本地 MVP 可同步级联，生产环境允许异步执行，但用户确认后不提供恢复。

补充接口：

```http
DELETE /v1/me/conversations/{conversation_id}
```

### 13.10 临时附件配额与生命周期

- 单文件上限 `25 MB`；
- 单次消息最多 `5` 个附件；
- 每位 owner 的临时附件总量上限 `200 MB`；
- 临时附件保持 conversation scope，只能在所属对话检索；
- 归档对话不会删除附件；
- 删除附件或删除对话时清理其私有索引和未被知识库引用的原始文件；
- “保存到个人知识库”复用同一 owner 私有文件对象并新增 knowledge relation，不复制正文与向量；
- 保存后删除原对话不会删除知识库文件。

生产环境原始文件进入私有对象存储；本地 MVP 可使用 owner 隔离的受控目录。任何情况下都不能将客户端文件名直接用作服务器路径。

## 14. 加载、错误与边界状态

- 初次加载：先显示稳定背景与输入区骨架；历史加载失败不能阻止新对话。
- 回复中：泊泊显示轻微思考状态，文本按真实流事件出现，用户可以停止本轮生成。
- 网络失败：保留原文、附件和重试入口，不自动重复提交外部副作用请求。
- 历史为空：左栏显示真实空状态，不填充 demo 内容。
- 右侧无关联：不显示空红点，主动展开时显示“这段对话还没有需要整理的内容”。
- 附件失败：说明格式不支持、文件过大、无法解析或服务不可用；失败文件不能被模型引用。

## 15. 响应式规则

- `>= 1440px`：左右两栏可同时展开；
- `1100–1439px`：展开右侧时自动收起左侧，反之亦然；
- `720–1099px`：左右栏均为覆盖式抽屉，中间对话保持全宽；
- `< 720px`：顶部导航简化，历史和关联从左右侧滑入，输入区避开安全区与软键盘；
- 响应式自动收起不覆盖用户在桌面端保存的偏好。

## 16. 可访问性与性能

- 消息区域使用正确的 log/list 语义，新回复通过非打断式 live region 提示；
- 左右抽屉支持键盘打开、关闭和焦点返回；
- 拖动对话进入文件夹必须同时提供菜单操作；
- 上传进度、解析状态和错误不能仅靠颜色表达；
- 动态背景、泊泊和玻璃高光遵循 reduced-motion；
- 正文和输入文字达到 WCAG AA 对比度；
- 背景层只动画 transform 和 opacity，不因滤镜变化持续重绘整屏；
- 长对话使用窗口化或分段加载，避免一次渲染全部历史。

## 17. 验收标准

- 新用户进入页面后无需配置即可发送第一条消息；
- 首页首条消息可进入同一 conversation，并在对话页继续；
- Agent 自动选择支持方式，页面不存在模式选择负担；
- 左侧可以创建、搜索、归档和用文件夹整理历史对话，并可收起；
- 右侧关联抽屉默认收起，新结果只提示、不自动打断；
- 罗盘、航程、知识库写入前需要确认，Dreaming 线索无需确认；
- PDF、DOCX、TXT 和 Markdown 可以上传、解析、引用和删除；
- 临时附件不会未经确认进入个人知识库或长期记忆；
- 回复、引用、附件状态和关联确认来自真实后端，不回退成 demo 数据；
- 桌面、平板、手机和 reduced-motion 模式下均可完成核心对话流程；
- 动态背景和玻璃效果不显著影响输入延迟、滚动与文字清晰度。
