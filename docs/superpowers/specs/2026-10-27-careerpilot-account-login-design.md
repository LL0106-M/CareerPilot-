# CareerPilot 账户登录设计

## 1. 目标

把当前匿名 `careerpilot_owner` Cookie 和线上临时 Clerk 登录替换为 CareerPilot 自己的一套
账户体系。用户用“用户名 + 邮箱 + 密码 + 邮箱验证码”注册，注册成功后必须回到登录页重新登录；登录时
可以选择是否记住登录状态。登录后，聊天、记忆、资料、罗盘、航程等数据都稳定归属于该
账户，而不是归属于某个浏览器生成的匿名 ID。

本阶段要解决的是完整、可部署的登录闭环，不只是画一个登录页面。

## 2. 已确认的体验

### 注册

- 字段：用户名、邮箱、邮箱验证码、密码、确认密码。
- 用户名和邮箱都必须唯一；比较时忽略大小写，展示时保留用户填写的用户名。
- 用户先填写邮箱并点击“发送验证码”，CareerPilot 通过网易 SMTP 发送 6 位数字验证码；
  验证码通过后才能创建账户。
- 验证码 10 分钟有效，60 秒后才能重发；同一邮箱和来源地址每小时最多发送 5 次。
- 每个验证码最多尝试 5 次；发送新验证码会立即作废旧验证码，验证成功后验证码只能消费一次。
- 密码允许粘贴和使用浏览器密码管理器，提供显示/隐藏按钮和明确的校验信息。
- 注册成功不自动登录，清空密码并跳转登录页，显示“注册成功，请登录”。
- 第一阶段不做找回密码；界面不伪装成已经支持该能力。

### 登录

- 使用“用户名或邮箱 + 密码”登录。
- 登录失败统一提示“用户名、邮箱或密码不正确”，不暴露某个账户是否存在。
- `记住我（5 天内免登录）` 默认不勾选。
- 不勾选：使用浏览器会话 Cookie；正常关闭浏览器后需要重新登录，同时服务端设置 24 小时
  绝对上限，避免通过浏览器会话恢复无限延长登录。
- 勾选：使用持久 Cookie；连续 5 天没有访问即过期。每次有效访问更新服务端 `last_seen_at`，
  但最多每小时写一次，避免每个请求都写数据库。
- 被记住的会话仍设置 30 天绝对上限；即使持续使用，满 30 天也必须重新登录。
- “记住我”只保存随机会话，不保存明文密码。是否保存密码由浏览器密码管理器决定。

### 登录后的页面

- 应用启动先请求 `/v1/auth/me`，确认身份前显示统一启动状态，不提前请求岗位、Dashboard 等业务数据。
- 未登录只能访问 `/login` 和 `/register`；访问其他地址时跳转登录页，并在成功登录后返回原地址。
- 登录后进入 Today 首页；导航区域展示用户名，并提供明确的“退出登录”。
- 设置页从真实 `/v1/auth/me` 显示用户名和邮箱，不再展示“临时身份”。
- 新账户的个人数据页面显示真实空状态，不出现演示记忆、演示 Dreaming 或假对话历史。
- 公共岗位和学习资料也放在登录保护之后，保证“进入平台就先登录”的产品约束一致。
- 收到 `401` 时，前端清空当前账户状态并跳转登录页；不得把未认证错误显示成普通数据加载失败。
- 退出时服务端撤销会话、删除 Cookie，前端清空内存缓存并回到登录页。

## 3. 后台数据模型

### `accounts`

- `id`: 随机 UUID，也是所有现有 owner-scoped 数据的新 `owner_id`
- `username`, `username_normalized`
- `email`, `email_normalized`
- `password_hash`
- `created_at`, `updated_at`, `last_login_at`
- `status`: 第一阶段只使用 `active`，为后续禁用账户保留边界

`username_normalized` 和 `email_normalized` 分别建立唯一索引。密码只保存 Argon2id 哈希，采用
`pwdlib[argon2]` 的推荐配置，不保存、记录或返回明文密码。

### `email_verification_challenges`

- `id`, `email_normalized`, `purpose=registration`
- `code_verifier`: 验证码与服务端密钥组合后的 HMAC，不保存 6 位原码
- `created_at`, `expires_at`, `last_sent_at`
- `attempt_count`, `consumed_at`, `invalidated_at`
- 用于限流的来源摘要；不把完整来源信息暴露给前端

请求验证码时只提交邮箱，不提交或暂存密码。最终注册请求同时提交用户名、邮箱、验证码和
密码；后端在一个事务中消费验证码并创建账户，避免“验证码已使用但账户没有创建”的中间状态。

### `auth_sessions`

- `id`: 公开查找 ID
- `account_id`
- `verifier_hash`: 随机会话密钥的 SHA-256 哈希；数据库不保存可直接复用的原始密钥
- `remember_me`
- `created_at`, `last_seen_at`, `idle_expires_at`, `absolute_expires_at`
- `revoked_at`

Cookie 保存 `session_id.verifier`，由加密安全随机数生成器产生。Cookie 名改为
`careerpilot_session`，设置 `HttpOnly`、生产环境 `Secure`、`SameSite=Lax`、`Path=/`。
服务端负责所有过期判断和撤销，不能只依赖前端计时或 Cookie 过期。

### 数据归属

所有现有 `owner_id` 查询继续使用同一接口，但值来自已验证会话的 `account_id`。这样聊天、
文档、记忆、Ideas、Dreaming、罗盘和航程不需要改表结构，只需要更换身份解析入口。

现有匿名数据不会在登录时自动并入任意账户，避免共享电脑上误认领他人数据。开发阶段的
旧匿名数据保留在数据库中但不可从账户访问，后续可单独编写一次性迁移工具。

## 4. API 合同

- `POST /v1/auth/verification-codes`: 为注册邮箱创建挑战并发送验证码；返回有效期和允许重发时间。
- `POST /v1/auth/register`: 校验邮箱验证码并创建账户；成功返回 `201` 和非敏感账户摘要，不创建会话。
- `POST /v1/auth/login`: 接收 `identifier`、`password`、`remember_me`；成功创建会话并设置 Cookie。
- `GET /v1/auth/me`: 返回 `{id, username, email}`；无效或过期会话返回 `401` 并清 Cookie。
- `POST /v1/auth/logout`: 撤销当前会话并清 Cookie；重复调用仍返回成功。

除健康检查、静态文件和上述认证入口外，所有 `/v1/me/*`、`/v1/chat`、运行状态及个人行动
接口都要求登录。公共知识接口虽然数据本身不私密，前端仍只在登录后调用。

验证码发送、登录与注册加入基础限流和统一错误信息；日志只记录账户 ID、结果和时间，不记录
密码、验证码、完整 Cookie 或会话 verifier。对 Cookie 鉴权的写请求校验同源 `Origin`，作为 `SameSite=Lax` 之外
的 CSRF 防线。

### 网易 SMTP 发信

- 新增与业务逻辑解耦的 `VerificationMailer` 接口；生产实现使用网易 SMTP，测试使用内存替身。
- 普通 163 邮箱默认使用 `smtp.163.com:465` 和 SSL/TLS；企业邮箱允许通过环境变量覆盖主机和端口。
- 配置项包括 `CAREERPILOT_SMTP_HOST`、`CAREERPILOT_SMTP_PORT`、
  `CAREERPILOT_SMTP_ACCOUNT`、`CAREERPILOT_SMTP_AUTHORIZATION_CODE` 和发件人名称。
- SMTP 使用网易“客户端授权码”，不是邮箱登录密码。授权码只存在服务端密钥配置中。
- 生产环境缺少 SMTP 配置时，验证码接口返回服务不可用，不生成可绕过邮件验证的测试码。
- 邮件正文只包含验证码、10 分钟有效期和忽略非本人操作的提示，不包含用户密码或内部账户信息。
- 发送失败时使本次挑战失效，并向前端返回可重试错误；界面不能显示“已发送”。

## 5. 前端结构与状态

- 新增 `AuthProvider`，只负责认证启动、登录、注册、退出和当前账户。
- 新增 `ProtectedRoute`，避免每个页面各自判断身份。
- 新增 `/login` 和 `/register` 两个无 AppShell 页面，沿用 CareerPilot 的安静、柔和视觉语言，
  但表单层级清晰，不使用 Clerk 的默认英文卡片或 Development mode 标识。
- 注册页按“填写邮箱并发码 → 输入验证码和账户资料 → 完成注册”推进；重发按钮显示 60 秒倒计时，
  邮箱变更后清除旧验证码状态。
- API 请求继续使用同源 HttpOnly Cookie；不把 token 放进 `localStorage`。
- `request()` 遇到 `401` 发出统一认证失效事件，由 `AuthProvider` 接管跳转。
- 登录提交期间禁用按钮；字段错误就近显示；服务端错误保留用户已填写的用户名或邮箱，清空密码。
- 注册和登录表单使用正确的 `autocomplete`：`username`、`email`、`new-password`、
  `current-password`，让用户自行选择浏览器是否保存密码。

### 桌面网页视觉

- 本阶段只实现桌面网页端；窄窗口保证表单可用，但不单独设计移动端导航。
- 登录和注册页不显示 AppShell、主导航或任何业务数据，使用现有浅米色背景和居中的
  `420px` 半透明白色卡片。
- 登录卡片包含 CareerPilot 标志、“欢迎回来”、用户名或邮箱、密码显示/隐藏、
  `记住我（5 天内免登录）`、墨绿色登录按钮和注册链接。
- 注册卡片沿用相同结构，依次提供用户名、邮箱、发送/重发验证码、验证码、密码、确认密码；
  发送后显示 60 秒倒计时。
- 不展示宣传轮播、第三方登录、无效的忘记密码入口或 Clerk Development mode。
- 登录后保留左上角 CareerPilot 标志；右上角显示泊泊头像和用户名。点击打开账户菜单，
  展示用户名、邮箱、“设置”和“退出登录”。
- 认证加载使用整页安静的启动状态，避免先闪现业务页面再跳回登录页。

## 6. 方案对比与决定

考虑过三种会话方式：

1. 纯浏览器会话：关闭浏览器即要求登录，但无法满足“记住我”。
2. 统一 5 天滑动会话：实现简单，但用户无法选择是否在设备上保留登录。
3. 混合会话：未勾选时使用会话 Cookie，勾选时使用 5 天闲置过期的持久 Cookie。

选择方案 3，因为它同时满足公共电脑上的谨慎使用和个人设备上的便利性。加入 24 小时/30 天
绝对上限，是实现层的安全约束；浏览器可能恢复会话 Cookie，所以“关闭浏览器”是主要体验，
服务端绝对上限才是可靠兜底。

账户实现采用仓库内 FastAPI + SQLite，而不是继续使用线上 Clerk。原因是当前所有业务数据已经
按后端 `owner_id` 隔离，自有账户可以直接成为该 owner；继续保留 Clerk 会形成第二套身份映射，
扩大目前前后端不协同的问题。

## 7. 非目标

- 忘记密码、修改密码和第三方登录。
- 多因素认证、设备管理和“退出所有设备”。
- 自动认领或合并旧匿名数据。
- 管理员后台；本阶段的“后台数据”指账户、会话及现有个人业务数据的可靠归属。

这些入口在实现前不出现在界面上，避免不可用按钮造成误导。

## 8. 验收标准

- 用户可注册；重复用户名或邮箱得到字段级错误；数据库中没有明文密码。
- 未通过邮箱验证码不能创建账户；过期、错误、重放和超过尝试次数的验证码均被拒绝。
- 网易 SMTP 授权码不进入前端、数据库或日志；生产环境无邮件配置时注册不能静默降级。
- 注册完成必须重新登录，用户名和邮箱均可作为登录标识。
- 未勾选“记住我”时产生会话 Cookie；勾选时产生最长 5 天闲置期限的持久 Cookie。
- 服务端能拒绝闲置过期、绝对过期、撤销或伪造的会话。
- 未登录访问业务页面和 API 均无法读取个人数据。
- 登录后刷新页面仍保持当前会话；退出后旧 Cookie 不能再访问 API。
- 两个账户的聊天、资料、记忆、Dreaming、罗盘和航程严格隔离。
- 页面启动不会在认证确认前发业务请求，线上控制台不再出现登录页提前请求数据的 `401`。
- 桌面网页提供可用的登录/注册表单；未登录时看不到 AppShell，登录后右上角显示当前账户菜单。
- Clerk 开发模式资源和当前匿名 `careerpilot_owner` 身份路径从生产登录流程中移除。
- 后端认证/API 测试、前端路由/表单测试、类型检查和生产构建全部通过。
