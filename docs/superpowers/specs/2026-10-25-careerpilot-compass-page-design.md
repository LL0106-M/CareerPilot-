# CareerPilot 罗盘页设计

## 1. 设计意图

罗盘页不是要求用户维护一套抽象的“自我模型”，而是帮助用户看清两件具体的事：

1. 我最近正在了解哪些职业；
2. 我一路上留下了哪些还没有成形、但值得保留的想法。

页面面向仍在探索、尚未形成稳定职业结论的用户。用户不需要先理解“假设、证据、约束”等产品术语，也不需要填写复杂表单。泊泊负责从对话、记录和行动结果中提出候选职业、整理线索；用户只需浏览、纠正、确认或暂时放下。

罗盘页与航程页的分工明确：罗盘回答“我在了解什么，以及为什么”，航程回答“下一步通过什么真实行动了解它”。

## 2. 已选方向

采用一个路由内的双章节沉浸式结构，用户通过纵向滚动从职业探索进入想法收藏：

```text
第一章：我正在了解的职业
          ↓ 滚动过渡
第二章：我收集的小想法
```

视觉参考来自用户提供的视频，但只迁移其空间组织方式：全屏场景、编辑式大标题、错落卡片、鼠标聚焦与滚动转场。不会复制旅行网站的品牌、图片内容或导航结构。

### 2.1 考虑过的方案

1. **双章节纵向叙事（已选）**
   - 优点：符合用户此前提出的“可以滑动”，两个部分既相互关联又各自完整；可以自然表达“方向来自零散想法”。
   - 代价：需要控制滚动动画，避免页面像展示站而不像工具。

2. **顶部标签切换**
   - 优点：操作直接，实现成本低。
   - 代价：割裂职业与想法的关系，也失去视频参考中最有价值的空间叙事。

3. **左右同时显示**
   - 优点：信息总览效率高。
   - 代价：容易退化成仪表盘，增加用户一进入页面时的认知负担，不符合“陪伴式探索”。

## 3. 页面整体框架

- 全页沿用统一的暖磨砂视觉语言，但不使用一块覆盖全屏的共同玻璃。
- 背景为低对比、缓慢变化的山谷与路径场景；第一章偏晨雾暖绿，第二章随滚动过渡到更深的暮色松绿。
- 顶部沿用全站导航：首页、对话、罗盘、航程、知识库。导航为独立悬浮毛玻璃胶囊，罗盘处于当前状态。
- 页面默认自然滚动，不强制锁死滚轮。桌面端仅在接近章节边界时提供轻微吸附；移动端完全使用自然滚动。
- 页面右侧提供极弱的章节标记 `01 Exploring / 02 Thoughts`，用于说明当前位置，不承担主要导航职责。

## 4. 第一章：我正在了解的职业

### 4.1 用户目标

用户进入后应在几秒内回答：

- 泊泊目前认为我在关注哪个具体职业；
- 这个职业为什么会出现；
- 我接下来最需要弄清楚什么。

本章不展示抽象的“当前方向”，而展示具体职业，例如“AI 产品经理”“国企数字化产品岗”“数据产品经理”。

### 4.2 首屏构图

首屏为一个完整场景，而非卡片网格：

```text
┌──────────────────────────────────────────────────────┐
│ 品牌       [首页 对话 罗盘 航程 知识库]        用户   │
│                                                      │
│ 01 / EXPLORING                         正在了解  3    │
│                                                      │
│      我为什么会来到这里      ┌──────────────────┐    │
│      来自 3 段对话与 1 个想法 │                  │    │
│                               │   AI 产品经理     │    │
│                               │                  │    │
│                               │  当前最想弄清：   │    │
│                               │  我是否喜欢长期   │    │
│                               │  处理模糊问题？   │    │
│                               └──────────────────┘    │
│                                                      │
│   ← 上一个                              下一个 →      │
│                          向下，看看这些方向从哪里来 ↓ │
└──────────────────────────────────────────────────────┘
```

中央职业卡不是普通白色面板，而是一张悬浮于背景前的半透明“目的地卡”：

- 卡片约占桌面宽度的 `32–38%`，保留大量负空间；
- 使用暖灰透明底、细颗粒、柔和内高光与很浅的琥珀色边缘；
- 标题使用高对比衬线字体，功能文本使用干净的无衬线字体；
- 卡片背后可出现非常弱的行业意象或抽象地形，不使用俗套职业图库；
- 鼠标移动时卡片只有 `2–4px` 的视差和不超过 `1.5°` 的倾斜。

### 4.3 职业卡信息层级

职业卡默认只显示四层信息：

1. 职业名称；
2. 探索状态；
3. 当前最想弄清的问题；
4. 一个轻量动作。

探索状态使用自然语言：

- 刚刚注意到
- 正在了解
- 正在验证
- 暂时放下
- 已经排除

主动作随状态变化：

- 刚刚注意到：`看看它为什么出现`
- 正在了解：`继续聊聊`
- 正在验证：`查看验证行动`
- 暂时放下：`重新拾起`
- 已经排除：`看看当时为什么排除`

不在默认卡面放置信心百分比、匹配度雷达图或大量标签，避免制造伪精确。

### 4.4 “为什么出现”

职业卡左侧放置一句极短解释，例如：

> 你反复提到喜欢把复杂信息变清楚，也在意工作是否能产生真实影响。

下方显示来源摘要：`来自 3 段对话 · 1 个想法 · 1 次行动反馈`。点击后从右侧打开轻量证据抽屉，展示可追溯来源，而不是在首屏铺满引用。

证据抽屉中的内容分为：

- 你说过的；
- 你做过的；
- 泊泊的理解。

“泊泊的理解”必须被明确标记为推测。用户可以选择“是这样”或“不太对”，反馈会调整该职业的解释，但不会删除原始对话或想法。

### 4.5 切换职业

- 桌面端支持鼠标拖动、触控板横向滑动、左右箭头和键盘方向键；
- 移动端使用水平滑动；
- 切换时当前卡片沿小弧线退到背景，下一张从另一侧进入；
- 周围最多露出前后各一张卡片的边缘，提示存在其他职业，但不形成拥挤轮播；
- 切换动画 `420–560ms`，使用缓入缓出，不模拟纸牌快速甩动。

### 4.6 状态修改与确认

泊泊可以自动提出候选职业，但以下操作必须由用户确认：

- 将候选职业正式加入罗盘；
- 将职业改为“已经排除”；
- 将想法关联到某个职业；
- 从职业创建航程验证行动。

“暂时放下”和“重新拾起”是低风险操作，可直接执行并提供撤销。所有确认在当前上下文内完成，不使用全屏弹窗。

## 5. 两章之间的滚动转场

第一章底部不是常规分割线。用户继续向下时：

1. 中央职业卡缓慢向上缩小，成为一个远处的“目的地”；
2. 卡片左侧的来源摘要拆成几枚轻量线索；
3. 线索沿柔和曲线向下散开，逐渐变为第二章的想法卡片；
4. 背景从晨雾过渡为更深的松绿，中央标题出现：`Thoughts worth keeping.`；
5. 转场结束后，卡片停止自动移动，控制权完全交还给用户。

动画只表达“方向来自这些思考”，不暗示系统已经自动把所有想法归类。若用户开启减少动态效果，转场替换为简单淡入和位置变化。

## 6. 第二章：我收集的小想法

### 6.1 用户目标

这一章不是备忘录列表，而是一面可以回看的思绪收藏墙。它让用户看见：过去随手记下的内容正在积累，其中有些可能与职业探索产生联系。

### 6.2 视觉结构

重点借鉴参考视频第二部分的错落照片墙：

```text
┌──────────────────────────────────────────────────────┐
│ 02 / THOUGHTS                             记录一个 + │
│                                                      │
│                Thoughts worth keeping.               │
│                                                      │
│   今年十月     ╱──────╲     ┌─────────┐    关于创造  │
│              │ 想做能把 │   │也许我不怕│              │
│     ┌──────┐ │复杂事讲清│   │变化，只怕│   ┌──────┐   │
│     │更喜欢│ ╲──────╱     │没有成长 │   │国企的│   │
│     │探索而│      ┌────────┐└─────────┘   │稳定… │   │
│     │非维护│      │被选中的│               └──────┘   │
│     └──────┘      │想法卡片│                          │
│                   └────────┘             与职业相关  │
│                                                      │
│        [全部] [未关联] [AI 产品经理] [稳定与成长]     │
└──────────────────────────────────────────────────────┘
```

想法卡片不是完全拟真的拍立得：保留轻微错落和层叠，但使用半透明暖磨砂材质，以保持全站一致。每张卡只显示原句的前 `28–48` 个中文字符、记录日期和来源图标。

### 6.3 空间与排布规则

- 桌面端首屏同时出现 `7–12` 张卡，中央疏、两侧密，给标题留出呼吸空间；
- 卡片旋转角度控制在 `-4°` 至 `4°`，避免手账感过重；
- 卡片不会互相完全遮住，至少保留可识别的标题区域；
- 排布由稳定的布局种子决定，同一批数据刷新后位置不乱跳；
- 新想法从右下方缓慢进入并找到位置，而不是突然插入顶部；
- 数据较多时通过继续纵向滚动加载下一组，不做无限缩小的全景画布。

### 6.4 鼠标与聚焦交互

- 鼠标移动只产生低幅视差，前景卡移动略多、背景卡移动略少；
- hover 卡片上浮 `8–12px`、轻微归正，并压暗其后的卡片；
- 点击后卡片移动到中央并放大，周围内容退到背景；
- 聚焦态右侧出现一条细信息栏，显示完整内容、记录时间、来源和关联建议；
- `Esc`、点击空白处或关闭按钮退出聚焦态；
- 键盘用户可通过 Tab 依次访问卡片，聚焦效果与 hover 等价。

### 6.5 想法详情

想法被选中后显示：

- 原始文字；
- 创建时间；
- 来源：首页快速记录 / 对话中保存 / 罗盘内记录；
- 当前状态：只是记下 / 正在发酵 / 已关联方向 / 已产生行动 / 已归档；
- 泊泊发现的可能关联；
- 用户动作。

主要动作保持克制：

- `和泊泊聊聊`
- `关联到职业`
- `暂时收起`

“关联到职业”需要用户确认。系统可以说“这可能与 AI 产品经理有关，因为……”，但不能自动建立正式关联，也不能自动生成航程任务。

### 6.6 “我做选择时在意什么”

该内容不独立成为第三个复杂页面，而作为两章之间的解释层：

- 第一章职业卡旁显示最多三个选择关键词，例如“成长空间”“稳定性”“真实影响”；
- 第二章底部筛选胶囊允许按这些关键词查看相关想法；
- 关键词由泊泊根据对话、想法和行动反馈整理；
- 用户可点开查看来源，并选择“符合我”或“不准确”；
- 不提供让用户从零搭建价值观体系的复杂编辑器。

### 6.7 新建想法

第二章右上角保留 `记录一个 +`。点击后在当前位置展开一张空白小卡，而不是跳转页面或打开大型表单。

- 唯一必填项是正文；
- 不要求标题、分类、职业、优先级或截止时间；
- 保存后显示“已经替你收好”；
- 可以继续停留在想法墙，也可以点击“和泊泊聊聊”；
- 保存本身不触发模型回复，不自动分类为职业方向。

## 7. 内容状态

### 7.1 首次使用

当没有职业候选时，第一章不展示空白仪表盘，而显示泊泊和一句引导：

> 还没有需要你决定的方向。先告诉我，最近什么工作让你好奇？

提供一个进入对话页的输入入口。用户也可以继续下滑查看已记录的小想法。

### 7.2 有想法、无职业

第一章显示“泊泊还在听”，并选取两三条真实想法作为弱背景线索，但不伪造职业结论。第二章正常展示想法墙。

### 7.3 有职业、无想法

第一章正常展示。第二章保留场景与标题，中央只出现一张可输入的新卡：

> 不用想完整，先把刚刚冒出来的那句话放在这里。

### 7.4 加载与失败

- 初次加载使用与最终布局相同的低对比占位轮廓，避免卡片加载后大幅跳动；
- 某条来源加载失败时只在对应区域显示重试，不遮挡整页；
- 保存或确认失败时保留用户输入和聚焦状态，提供原地重试；
- 不以全局 toast 作为唯一反馈。

## 8. 动态背景与材质

- 第一章背景：暖灰天空、雾绿山谷、远处小径；运动主要来自雾层和光线，循环周期 `18–30s`。
- 第二章背景：更深的松绿与暖黑，降低环境图像细节，让文字卡片清晰。
- 毛玻璃只用于导航、职业卡、想法卡和局部抽屉；背景本身保持完整，不覆盖统一的大玻璃面。
- 强调色只使用低饱和琥珀色，表示当前焦点、确认和职业关联。
- 玻璃透明度必须保证正文对比度；装饰性细字不承担唯一信息。

## 9. 响应式设计

### 9.1 桌面端（≥ 1100px）

- 保留完整沉浸式构图、错落卡片与低幅鼠标视差；
- 职业切换以横向为主，章节切换以纵向为主；
- 想法详情在中央放大，右侧出现信息栏。

### 9.2 平板端（720–1099px）

- 职业卡居中，来源解释移至卡片下方；
- 想法墙减少为 `5–8` 张卡，取消两侧文字索引；
- 详情信息栏改为底部抽屉。

### 9.3 移动端（< 720px）

- 取消复杂视差和章节吸附；
- 职业使用单张横滑卡片；
- 想法改为轻微错落的双列流，不让卡片互相遮挡；
- 详情使用近全屏底部抽屉；
- 新建想法按钮固定在安全区域内，但不覆盖全站导航。

## 10. 可访问性与减少动态

- 所有拖动操作都有按钮和键盘替代；
- 当前职业、卡片位置和确认结果有可读的状态文本；
- 不依赖颜色区分职业状态；
- 正文和玻璃背景达到可读对比度，背景图在文字区域自动加暗；
- 尊重 `prefers-reduced-motion`：关闭视差、倾斜、路径飞行和章节吸附；
- 屏幕阅读器中的想法按时间顺序排列，不按视觉散落顺序朗读；
- 聚焦想法时正确管理焦点，退出后返回原卡片。

## 11. 与其他页面的关系

### 11.1 首页

- 首页记录的小想法直接进入第二章；
- 保存成功只表示“已收好”，不表示已分析或已关联；
- 首页可以通过弱链接直接定位到新想法卡片。

### 11.2 对话页

- 泊泊在对话中提出职业候选，用户确认后进入第一章；
- 用户确认保存的想法进入第二章；
- 从职业卡或想法卡发起对话时，携带可见的上下文摘要，不自动发送用户未确认的消息。

### 11.3 航程页

- 第一章可以提出“用一个真实行动验证它”；
- 只有用户确认后才创建航程任务；
- 航程完成后的结果回流为职业卡的证据与状态建议，但不自动排除职业。

### 11.4 Dreaming

- Dreaming 可以无确认地读取罗盘中的真实线索，形成陪伴式观察；
- Dreaming 的推测不能直接修改职业状态、建立职业关联或创建航程任务。

## 12. 建议的数据模型与接口边界

本设计不要求用户看到内部术语，但实现层需要稳定对象：

### 12.1 职业探索项

```text
CareerExploration
- id
- title
- state
- current_question
- rationale_summary
- evidence_counts
- value_keywords[]
- created_at
- updated_at
```

### 12.2 想法

沿用现有 Idea Product State，并补充展示需要的字段：

```text
Idea
- id
- body
- stage
- source_type
- source_id?
- suggested_links[]
- confirmed_links[]
- created_at
- updated_at
```

建议的页面读接口返回两个章节的聚合数据，避免前端逐卡请求；来源详情、想法详情和关联建议可以按需加载。所有新增、确认和状态修改请求必须支持幂等键，防止滚动场景中的重复操作。

### 12.3 泊泊何时整理罗盘

罗盘采用“事件触发、后台整理、用户确认写入”的机制，不在用户每次打开页面时重新生成，也不在单独保存小想法时同步调用模型：

1. 一段有效对话结束后，Agent 可以在后台产生职业候选、当前问题、关联建议和选择关键词；
2. 航程任务完成并提交反思后，系统可以重新评估对应职业的当前问题与状态建议；
3. Dreaming 完成一次线索整理后，可以提出新的解释或关联建议；
4. 单独保存小想法只持久化原文。只有当后续对话、Dreaming 或定时整理过程使用到它时，才生成建议；
5. 后台生成的内容先进入 `suggested` 状态。除 Dreaming 观察外，任何正式职业、关联或状态变化仍遵守本设计的确认边界。

本轮需要在现有 Agent 与 Product Store 之上增加罗盘整理服务与可重试的后台作业；前端不直接拼装模型输出。相同来源版本只能产生一个有效整理作业，失败不阻塞原始对话、想法或航程结果的保存。

### 12.4 职业状态机

状态变化遵循以下规则：

```text
候选建议 --用户确认--> 刚刚注意到
刚刚注意到 --用户开始阅读/对话--> 正在了解
正在了解 --用户确认验证行动--> 正在验证
正在验证 --仍需更多了解--> 正在了解
任意活跃状态 --用户直接操作--> 暂时放下
暂时放下 --用户重新拾起--> 放下前的活跃状态
任意活跃状态 --用户确认--> 已经排除
已经排除 --用户重新考虑--> 刚刚注意到
```

泊泊与航程结果只能提出状态建议，不能自动进入“已经排除”。“正在了解”可以由用户主动打开该职业并发起对话后自动进入，因为它只描述用户已经发生的低风险行为；“正在验证”只在用户确认创建验证行动后进入。

### 12.5 用户否定泊泊的理解

用户选择“不太对”或“不准确”后：

- 当前推测立即标记为 `rejected`，不再作为职业解释或关键词展示；
- 保留来源事实，不删除原始对话、想法或行动反馈；
- 原地出现一个非必填的短输入：`更接近你的说法是什么？`；
- 用户可以直接关闭，也可以写一句纠正；纠正内容作为用户确认的信息保存；
- 系统不会在原地连续重新生成答案。需要继续澄清时提供 `和泊泊聊聊`，进入对话页并携带被否定的推测摘要。

### 12.6 与航程创建流程的边界

罗盘不承担完整的行动编辑器。用户点击“用一个真实行动验证它”后，罗盘只生成一张可读的行动草案，包含：想验证的问题、建议行动、预计投入和完成后要回答的问题。

- 用户点击 `去航程确认` 后进入航程页；
- 行动的修改、日期、状态与最终创建都由航程页承接；
- 未进入航程确认的草案不创建正式任务，也不把职业改为“正在验证”；
- 一个职业可以关联多个验证行动；职业卡默认突出当前未完成或最近完成的一项，其余在来源抽屉中查看；
- 航程页的具体编辑与排期交互留待航程页设计确定，罗盘只约定交接数据，不预先复制该界面。

## 13. 非目标与反目标

本轮不做：

- 职业测评问卷；
- 匹配度评分或雷达图；
- 让用户手动维护完整价值观体系；
- 自动把想法变成任务；
- 自动排除职业；
- 无限画布或复杂节点图；
- 在罗盘页内复制完整聊天界面。

即使视觉精美，如果用户仍不知道职业为什么出现、下一步要了解什么，或需要学习一套产品术语才能操作，都视为设计失败。

## 14. 验收标准

- 罗盘只有两个清晰章节：职业探索与小想法；
- 用户首次进入可在数秒内说出当前正在了解的具体职业；
- 每个职业都能解释来源并显示一个当前问题；
- 想法墙保留参考视频的错落、聚焦和动态感，但维持暖磨砂品牌语言；
- 小想法可以直接记录，不要求分类；
- 系统建议与用户确认有明确边界；
- 职业关联、排除和创建航程行动都需确认；
- 桌面端动态有高级感，移动端与减少动态模式仍可完整使用；
- 页面能与首页、对话、航程和 Dreaming 形成真实数据闭环。
