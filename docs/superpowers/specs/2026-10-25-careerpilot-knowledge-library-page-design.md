# CareerPilot 知识库页面设计

## 1. 设计意图

知识库是用户与泊泊共同积累职业材料的地方。它不是文件管理器，也不是把全部数据库记录一次铺在页面上的后台表格。

页面包含三个内容域：

1. **个人资料**：用户上传的简历、作品集、个人陈述、证书和项目材料；
2. **岗位信息**：由用户在对话中明确触发搜索后发现并直接进入知识库的岗位；
3. **学习资料**：Agent 收集的公开网页、系统精选资源以及用户上传或手动填写的往年考题和学习资源。

数据库可以长期积累大量内容，但知识库首页只显示有限、最值得继续的内容。完整内容通过“查看全部”、结构化筛选和游标分页访问。

## 2. 已确认的产品决定

- 三个库位于同一个 `/knowledge` 页面内，以局部分类切换，不拆成三个一级导航。
- 页面内第一版只做结构化筛选和普通关键词匹配，不提供面向用户的自然语言语义搜索框。
- 自然语言搜索由对话页承担；用户明确发起“搜索岗位、找资料、收集资料”等请求时，经过校验的结果直接进入其知识库。
- 普通回答中临时引用的网页不自动入库。
- 知识库中央推荐位优先显示用户手动指定的内容；没有手动指定时显示最近一次对话搜索批次；仍没有时显示系统精选集合。
- 用户的三个库分别保存自己的中央推荐位。
- 个人资料库不预置虚假用户简历；岗位库不预置虚构岗位、截止日期或链接；真实预置内容主要进入学习资料库。
- AI 不是新的强制分类，而是首批编辑精选集合和资源标签。资料仍按学习目的保持稳定分类。

## 3. 方案选择

### 3.1 考虑过的结构

1. **有限首页 + 完整列表（已选）**
   - 首页负责发现、继续和聚焦；完整列表负责筛选与管理。
   - 能复用用户提供的书库参考图，同时允许数据库持续增长。

2. **进入即显示完整表格**
   - 数据密度高，但首屏像后台管理系统，缺少陪伴感和内容优先级。

3. **无限瀑布流**
   - 浏览轻松，但岗位字段、来源、截止日期和筛选状态不易比较，也不利于回到某次对话搜索。

### 3.2 自动入库方式

采用“公共规范记录 + 私人知识库关联”，不为每位用户复制一份相同网页或岗位：

```text
公开岗位 / 公开学习资源
          ↑
user_library_entries
          ↓
用户私有的浏览、收藏、备注、航程关联和来源对话
```

用户上传内容始终为私有记录，并在查询和检索阶段按用户隔离。

## 4. 整体视觉方向

页面参考用户提供的书库界面，但只迁移信息结构：顶部分类、左侧近期内容、中央聚焦内容、下方横向内容架和“查看全部”。

- 全页背景延续暖色动态山谷或室内书架般的柔和光影，运动极慢；
- 主内容位于一块有边界但不浑浊的暖磨砂框架内；
- 框架内部的左栏、中央主卡和横向内容卡仍保持独立层级，不形成一整块无差别玻璃；
- 三个内容域共享布局骨架，但卡片字段和主视觉不同；
- 资源封面不强制使用书籍封面。网页使用来源、主题和抽象图形组合，避免伪造原站封面或版权图片。

## 6. 中央推荐位

### 6.1 优先级

每个库独立遵守：

```text
用户手动指定
    ↓ 无有效指定
最近一次对话搜索批次
    ↓ 无搜索批次
系统精选集合或合适空状态
```

用户手动指定可以是：

- 个人资料：一份主简历、主作品集或资料集合；
- 岗位信息：一个重点岗位或一次岗位搜索批次；
- 学习资料：一份资料或一个编辑精选专题。

中央卡右上角提供低强调 `更换`，详情菜单提供 `取消指定`。取消后立即回退到最近搜索，不弹出复杂选择页。

### 6.2 数据结构

```text
knowledge_feature_preferences
- user_id
- library_kind: personal | jobs | learning
- featured_type: document | job | resource | discovery_batch | editorial_collection
- featured_id
- updated_at
```

每个 `user_id + library_kind` 只允许一个有效记录。目标被删除、失效或无权访问时，不物理删除偏好历史，但前端按回退规则展示下一级内容。

## 7. 左侧栏

### 7.1 最近加入

显示最近 `5–8` 项，不无限滚动：

- 个人资料：上传完成或完成解析的文件；
- 岗位信息：最近由对话搜索发现的岗位；
- 学习资料：Agent 收集、系统精选加入或用户上传的资料。

每项仅显示标题、类型、加入时间和必要状态。点击 `查看全部` 进入完整列表。

### 7.2 继续查看

只显示有明确进行状态的内容：

- 上次打开但未读完的学习资料；
- 当前主简历或待确认提取结果；
- 已加入航程的岗位；
- 正在准备的考题或资料；
- 解析失败、需要用户处理的上传文件。

没有内容时整个区块收起，不显示“暂无内容”占位。

## 8. 下方内容架

每个内容架首屏只显示 `4–6` 张卡片，支持克制的横向移动。卡片较多时通过 `查看全部` 进入完整列表，不做无限横滑。

### 8.1 个人资料

推荐内容架：

- 最近使用；
- 不同版本；
- 待确认档案信息。

卡片字段：标题、资料类型、文件格式、当前版本、更新时间和解析状态。

### 8.2 岗位信息

推荐内容架：

- 最近发现；
- 临近截止；
- 已收藏；
- 已关联航程。

岗位卡必须直接显示：

- 企业类型；
- 企业名称；
- 岗位名称；
- 岗位类型；
- 投递截止时间或“滚动招聘 / 未公开”；
- 来源或投递网页入口。

公司 logo 只有在具有可用、授权或官方来源时才显示；否则使用文字标识，不抓取模糊第三方图片。

### 8.3 学习资料

推荐内容架：

- 与当前航程相关；
- AI 如何进入不同职业；
- 往年考题；
- 最近收集；
- 继续学习。

卡片字段：资料类型、主题、来源、访问条件、更新时间；考题额外显示笔试/面试、企业、岗位、年份和是否包含答案。

## 9. 完整列表与筛选

点击 `查看全部` 后在同一知识库框架内进入列表状态，保留顶部三个库的切换。

### 9.1 个人资料筛选

- 资料类型；
- 文件格式；
- 解析状态；
- 更新时间；
- 当前版本。

### 9.2 岗位信息筛选

- 企业类型；
- 企业名称；
- 岗位类型；
- 地点；
- 招聘类型；
- 截止状态；
- 收藏、投递和航程关联状态；
- 排序：相关性、最近发现、截止时间、最近验证。

### 9.3 学习资料筛选

- 往年考题 / 学习资源；
- 笔试 / 面试；
- 题目类型；
- 企业；
- 岗位类型；
- 年份；
- 学习资源分类；
- 来源；
- 文件格式；
- 是否包含答案；
- 访问条件。

筛选状态写入 URL 查询参数，允许从对话深链接进入并自动填充。结果使用游标分页；普通页码可作为视觉表现，但后端不依赖高偏移量查询。

## 10. 对话搜索与直接入库

### 10.1 触发条件

只有用户明确表达知识搜索意图时自动入库，例如：

- “搜索北京央企的产品岗位”；
- “找阿里云近三年的产品面试题”；
- “收集几份 AI 在金融领域的可靠资料”。

普通事实问答中临时引用网页不自动保存。用户说“不要保存”时，本次只返回临时结果。

### 10.2 数据流程

```text
用户明确搜索
→ Agent 输出受约束的 SearchSpec
→ 后端验证枚举、日期、范围和用户权限
→ 查询已有结构化数据并按需联网补充
→ 验证来源、规范化 URL、去重
→ 公共记录 upsert / 私有上传建立私有记录
→ 创建用户知识库关联和 discovery batch
→ 对话返回有限结果
→ 知识库出现“刚刚找到”
```

LLM 不生成 SQL，也不直接写数据库。它只能产生后端 Schema 允许的结构化搜索条件。

### 10.3 每批范围

- 每次明确搜索最多自动加入前 `20–30` 条经过校验的结果；
- 搜索引擎候选、重复结果和来源不可验证内容不进入用户知识库；
- 对话显示前 `3–5` 条并提供 `在知识库查看全部`；
- 再次搜到同一项时更新 `last_seen_at` 并关联新批次，不覆盖用户备注、收藏和航程状态。

### 10.4 搜索批次

```text
knowledge_discovery_batches
- id
- user_id
- target_type: jobs | learning
- conversation_id
- original_query
- parsed_filters_json
- result_count
- created_at

knowledge_discovery_results
- batch_id
- item_type
- item_id
- rank
- reason_summary
```

```text
user_library_entries
- id
- user_id
- item_type
- item_id
- added_by: agent_search | user_upload | user_manual | system_recommendation
- source_conversation_id?
- source_message_id?
- discovery_batch_id?
- state: new | viewed | active | completed | archived
- pinned
- first_added_at
- last_seen_at
- archived_at?
```

### 10.5 自动入库的来源校验

“经过校验”不只表示链接可以打开，还必须满足来源身份、关键字段和内容一致性要求。

#### 岗位信息

来源分级：

```text
official       企业官网、官方招聘平台或官方公众号可追溯页面
authoritative  高校就业中心、政府招聘平台或能明确回链原始发布页的平台
aggregator     商业招聘聚合站
community      论坛、社交媒体、个人转载或聊天截图
```

自动入库规则：

- `official`：关键字段通过解析和基本一致性校验后可直接入库；
- `authoritative`：必须保留发布机构和原始链接；与原始页面可核对时可直接入库；
- `aggregator`：只有能够追溯到企业原始招聘页，或至少同时具备明确公司、岗位、投递入口和最近验证时间时，才作为正式岗位入库，并标注为二手来源；
- `community`：不能单独成为正式岗位记录，只能作为待核实线索。找到官方或可靠来源后才升级为岗位；
- 企业名称、岗位名称或来源链接任一缺失时，不自动入库；
- 企业类型无法确定时允许 `organization_type=unknown`，页面显示“企业类型待确认”；
- 岗位类型无法确定时允许 `role_family=unknown`，但必须保留岗位原始名称；
- 截止时间未公开时允许 `deadline_at=NULL`、`deadline_precision=unknown`，页面显示“截止时间未公开”，不得猜测日期；
- 投递链接和信息来源链接可以相同，但至少存在一个可访问且可追溯的链接；
- 链接可访问、字段完整、内容一致和验证时间都需记录，过期后进入重新核验流程。

#### 学习资源

来源分级：

```text
official       官方文档、政府、国际组织、大学、企业官方课程
authoritative  专业协会、学术机构、正式出版物、维护良好的开源课程
community      专业社区文章、个人教程、经验整理
user_provided  用户上传或手动填写
```

- `official` 与 `authoritative` 在链接、标题、发布者和内容主题一致后可自动入库；
- `community` 可以入库，但必须明确展示来源等级和作者，不得包装成官方材料；
- 网页只有转载摘要且无法找到原文时，默认不抓取全文，只保存为带风险标记的外部线索；
- 无标题、无来源 URL 或与搜索主题明显不相关的内容不入库；
- 付费墙、登录要求和部分开放必须作为 `access_condition` 明确展示；
- 系统摘要只能概括可访问内容，不得绕过访问限制抓取受限全文。

#### 往年考题与面经

- 企业公开样题可标记为 `official_sample`；
- 高校就业中心、专业机构整理且有明确来源的内容可标记为 `authoritative_collection`；
- 论坛或个人分享只标记为 `candidate_recollection`，UI 使用“经验回忆 / 未经官方确认”，不能称为“官方真题”；
- 公司、笔试/面试类型和来源必须存在；年份、岗位或轮次未知时允许为空并明确显示“未说明”；
- Agent 提取出的单题在完成结构校验前保持 `draft`，不能进入正式题目筛选结果。

以上规则允许用户获得足够覆盖面，同时让“未知、未公开、经验回忆”保持可见，而不是用模型猜测补齐。

## 11. 三个库的详情行为

### 11.1 个人资料详情

- 文件预览和版本历史；
- 解析状态和引用定位；
- Agent 提取的个人档案候选；
- 接受、编辑或拒绝候选；
- `设为主简历 / 设为中央内容`；
- 删除使用异步传播，不立即伪装成已彻底清除。

### 11.2 岗位详情

- 必需字段和完整岗位描述；
- 来源、最近验证时间和截止精度；
- `收藏`、`加入航程`、`和泊泊聊聊`、`设为重点岗位`；
- 过期岗位保留历史，但不进入默认招聘中结果；
- 来源网页失效时显示状态，不抹掉用户投递和足迹记录。

### 11.3 学习资料详情

- 标题、摘要、来源、访问条件、更新时间；
- 原网页或文件入口；
- 资料分类、标签与适合的职业/航程；
- `关联航程`、`继续学习`、`和泊泊讨论`、`设为当前专题`；
- Agent 摘要必须与来源分开显示，不冒充原文；
- 用户上传资料保持私有；公开资料保留规范 URL 和内容快照。

## 14. 编辑精选的数据规则

```text
editorial_collections
- id
- slug
- title
- subtitle
- description
- cover_asset
- status
- display_rank
- published_at
- updated_at

editorial_collection_items
- collection_id
- item_type
- item_id
- display_rank
- curator_note
```

精选集合不改变资料分类。资源可以同时属于多个精选集合。系统精选进入页面不等于自动写入用户私人收藏；当它作为知识库空状态提供时，用户打开或手动保存后才创建 `user_library_entries`。用户手动把精选集设为中央内容时，创建对应偏好记录。

## 15. 来源、可用性与更新

- 每条系统精选记录 `last_verified_at`、访问条件和来源机构；
- 每月或每季度执行链接健康检查，不因一次超时立即删除资源；
- 页面失效时标记 `source_unavailable` 并保留历史；
- 资料内容更新时保存内容哈希和新快照，不覆盖旧引用；
- 仅保存用于检索和展示的必要摘要，遵守来源许可，不整页复制受版权保护内容；
- Agent 生成的中文摘要必须标注为“泊泊整理”，并保留原始链接；
- 用户上传资料默认私有，不参与系统精选。

## 16. 与其他页面的交互

### 16.1 首页

首页不放完整知识库，只可出现一条与当前对话或航程相关的资料入口。点击进入对应详情或精选集合。

### 16.2 对话页

- 自然语言搜索、结果解释和自动入库的主要入口；
- 返回结果卡和 `在知识库查看全部`；
- 从知识库进入对话时携带可见资料摘要，不自动发送消息；
- 用户明确要求不保存时使用临时搜索结果。

### 16.3 罗盘页

知识库资料可以作为职业探索的公共证据，但不能自动改变职业状态。岗位或资料与职业关联前需要用户确认。

### 16.4 航程页

- 行动可以关联简历、岗位、考题或学习资料；
- 创建飞书/WPS 文档后可将外部链接关联回知识库，但永久索引仍需确认；
- 岗位加入航程不会复制岗位记录，只建立关系；
- 学习资料完成状态可以进入足迹，但不自动完成航程行动。

### 16.5 Dreaming

Dreaming 可以观察用户长期关注的资料类型和真实学习行为，但不能因为用户打开一次网页就推断稳定偏好，也不能自动收藏、上传或公开用户内容。

## 17. 外部 App 与上传入口

- 个人资料和用户学习资料支持本地上传 PDF、DOCX、TXT、Markdown；
- 飞书或 WPS 创建的文档先以外部链接形式关联，是否抓取并索引必须再次确认；
- 外部文档访问失败时不影响站内其他知识记录；
- 外部写入继续遵守 `Preview → Confirm → Apply → Verify`；
- 页面根据后端实际能力展示入口，不显示尚未配置的 App。

## 18. 内容状态

### 18.1 个人资料空状态

不伪造文件，提供：

- 上传第一份简历；
- 查看简历与作品集模板；
- 了解泊泊会如何使用资料。

模板是系统资源，不出现在“我的文件”中，除非用户明确创建副本。

### 18.2 岗位信息空状态

不预置虚构岗位。中央区提供对话搜索入口：

> 告诉泊泊你想看的企业、岗位或地区。

提供可点击示例，如“探索 AI 产品岗位”“看看央国企数字化岗位”，点击进入对话并填入未发送提示。

### 18.3 学习资料空状态

展示首批系统精选集合。打开资源不等于用户已完成学习；用户可以保存、设为当前专题或关联航程。

### 18.4 加载与失败

- 各区域独立加载，中央内容失败不阻塞左栏；
- 上传和网页解析状态原地展示；
- 保存失败保留用户动作并允许重试；
- 不以全局 toast 作为唯一反馈；
- 链接不可用时提供来源状态，不静默移除用户记录。

## 19. 响应式设计

### 19.1 桌面端（≥ 1100px）

- 保留左侧双区块、中央主卡和横向内容架；
- 完整列表使用侧边筛选；
- 详情使用右侧抽屉或独立内容态。

### 19.2 平板端（720–1099px）

- 左栏改为中央主卡下方的横向“最近 / 继续”；
- 筛选使用顶部抽屉；
- 内容架每屏显示两至三张卡。

### 19.3 移动端（< 720px）

- 分类切换固定在顶部安全区域；
- 中央主卡优先，最近加入和继续查看变为折叠区；
- 卡片使用单列或两列；
- 筛选使用全屏底部面板；
- 不依赖 hover，所有菜单均有明确按钮。

## 20. 可访问性与减少动态

- 玻璃背景上的文字达到可读对比度，中央图片自动加暗以保护文本；
- 分类、筛选和卡片状态不只依赖颜色；
- 横向内容架提供按钮与键盘导航；
- 屏幕阅读器按标题、中央内容、最近加入、内容架和完整列表的逻辑顺序朗读；
- 尊重 `prefers-reduced-motion`，关闭卡片景深、背景漂移和内容架惯性动画；
- 来源链接、访问限制和 Agent 摘要标识必须可读。

## 21. 非目标与反目标

本轮不做：

- 在知识库页面提供自然语言语义搜索框；
- 把所有聊天引用网页自动保存；
- 用虚构岗位填充 UI；
- 用示例简历冒充用户文件；
- 全文复制第三方受版权保护资料；
- 自动公开用户上传内容；
- 用 AI 专题替换正式资料分类；
- 无限滚动展示全部数据库内容；
- 未经确认把外部文档导入私有检索库。

如果页面精美但用户无法知道内容来自哪里、为什么进入知识库、是否真实可用，或首页被持续增长的数据淹没，都视为设计失败。

## 22. 验收标准

- 页面包含个人资料、岗位信息和学习资料三个清晰内容域；
- 中央内容遵循“手动指定 → 最近搜索 → 系统精选”的回退规则；
- 首页只展示有限内容，完整记录可通过查看全部、筛选和分页访问；
- 对话中的明确搜索结果经过校验后直接进入知识库；
- 重复搜索不创建重复资源，不覆盖用户状态；
- 岗位卡完整显示企业类型、企业名称、岗位名称、岗位类型、截止时间和网页链接；
- 学习资料区区分往年考题与学习资源，并支持来源和类型筛选；
- 首批 AI 精选资料均有真实、可访问来源和访问条件；
- AI 作为专题和标签，不成为新的强制分类；
- 个人资料和用户上传资料保持私有；
- 页面与对话、罗盘、航程、Dreaming 和外部 App 的交互边界明确。
