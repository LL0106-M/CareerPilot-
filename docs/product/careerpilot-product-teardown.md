# CareerPilot 产品拆解

> 结构：产品概述｜四大产品功能｜三项横向技术能力｜总结与使用建议
> 定位：既可改编为小红书长图卡片，也可作为技术产品经理面试中的项目讲解主线

## 卡片 1｜产品概述

### CareerPilot：一个陪你理解自己、探索职业方向的 Personal Agent

CareerPilot 是一款面向高校学生与毕业早期青年的长期职业陪伴 Agent。

它关注的不是一次性职业测评，也不是通过一轮问答给出职业答案，而是用户在职业探索中持续产生的情绪、想法、经历与行动。

CareerPilot 希望解决三个问题：

- **不知道怎么表达：** 面对职业选择时，焦虑、自我怀疑和不确定性常常混在一起，用户需要先被理解。
- **不知道怎么判断：** 兴趣、经历、外界期待与现实约束相互交织，需要被逐步梳理。
- **不知道如何验证：** 即使产生了职业想法，也缺少低成本的现实尝试和持续反馈。

因此，CareerPilot 将情绪陪伴、认知澄清、职业探索与行动反馈连接起来，让职业方向不再是一次性的推荐结果，而是在真实经历中逐渐形成的判断。

> 它不替你决定未来，而是陪你在一次次真实尝试中，把方向走清楚。

**产品能力地图：**

```text
情绪陪伴与认知澄清 → 职业方向发现与探索 → 职业知识与证据支持 → 行动管理与认知进化
          └──────── 五类 Memory · 情绪响应控制 · Agent Context & Harness ────────┘
```

**配图建议：** 今日首页、对话页、罗盘页与航程页组成一条“表达—理解—验证—行动”的路径。

## 卡片 2｜核心功能一：情绪陪伴与认知澄清

### 不只是回答问题，而是判断用户此刻真正需要什么

**用户痛点：**

职业迷茫不完全是信息不足。用户可能只是想倾诉，也可能想理清困惑，或者已经准备好采取行动。

如果 Agent 每次都急于分析问题、检索职业知识和制定计划，反而会打断用户的表达。

**可见功能：**

- **情绪陪伴：** 识别焦虑、失落、自责等困扰信号，先接住感受，不强制把倾诉转化为任务。
- **认知澄清：** 帮助用户区分事实、感受、自我判断与证据，找到真正卡住自己的问题。
- **有限追问：** 对试探性的职业兴趣先追问来源与矛盾，不立即给出职业结论。
- **模式切换：** 根据用户状态在倾听、梳理、探索和行动之间调整回应方式。

**技术亮点：情绪感知与响应控制**

- `SupportPolicy` 根据困扰信号、明确倾听诉求和安全风险选择支持模式。
- `ResponseStrategyEngine` 将评估结果转成结构化 `ResponseContract`，约束回应的温暖程度、主动性、篇幅、追问目标与禁止行为。
- 四种支持模式分别是 `LISTEN`、`ORGANIZE`、`EXPLORE`、`ACT`。
- `IntentAwareRetrievalRouter` 根据支持模式限制上下文和工具；倾听模式默认不检索职业知识，也不主动创建任务。

**核心价值：**

情绪识别不是为了给用户贴标签，而是决定 Agent 应该如何回应，以及什么时候不应该主动介入。

**配图建议：** 同一句职业困惑在“倾听”和“行动”两种状态下的不同回应，并标注温度、篇幅、追问和工具调用差异。

## 卡片 3｜核心技术一：五类长期记忆

### 让 Agent 记住重要的经历，而不是简单保存聊天记录

**用户痛点：**

普通聊天机器人依赖有限的上下文窗口。每次重新开启对话，用户都可能需要重复介绍自己的背景、偏好和经历。

但长期陪伴型 Agent 需要理解的不只是用户说过什么，还包括用户经历过什么、形成了什么判断，以及希望 Agent 如何与自己协作。

**可见功能：**

1. **Working Memory（工作记忆）：** 当前消息、近期对话、页面状态和本轮工具结果，帮助 Agent 完成本轮任务。
2. **Episodic Memory（情景记忆）：** 具体经历，例如一次面试、职业尝试或重要选择。
3. **Semantic Memory（语义记忆）：** 相对稳定的事实、偏好、目标和现实约束。
4. **Procedural Memory（程序记忆）：** 用户偏好的协作方式，例如先分析再行动、不要连续追问。
5. **Prospective Memory（前瞻记忆）：** 未来需要触发的事项和待履行的承诺。

**技术亮点：记忆治理而非聊天归档**

- **选择性写入：** `MemoryWritePolicy` 判断表达是否具有长期价值，不是每轮对话都写入。
- **状态与版本：** 记忆支持 `candidate`、`active`、`paused`、`superseded`、`deleted` 等状态，并保留来源、置信度、敏感度和版本。
- **目的感知召回：** 根据陪伴、规划等不同用途，综合词项、中文语义片段、可用的向量相似度、重要性与时效性排序。
- **冲突与纠正：** 新表达和旧记忆冲突时，不静默覆盖；系统保留修订关系，允许用户纠正。
- **隐私保护：** 临时情绪和自我否定不会直接固化成稳定画像。

> **概念边界：** 五类 Memory 是功能架构，不代表五套彼此独立的存储引擎。当前底层记录按 `FACT`、`PREFERENCE`、`GOAL`、`CONSTRAINT`、`IDEA`、`EXPERIENCE`、`DECISION`、`HYPOTHESIS` 等业务类型存储；两层分类解决的是不同问题。

**核心价值：**

让 Agent 不只是“记得用户说过什么”，而是能为不同目的选择合适的个人信息，并允许用户持续修正系统对自己的理解。

**配图建议：** 中间是一条用户经历，向外连接五类记忆；底部补一行“功能分类 ≠ 独立存储引擎”。

## 卡片 4｜核心功能二：职业方向发现与探索

### 从一句模糊的职业想法，到一个由用户确认的方向

**用户痛点：**

很多用户并不是没有兴趣，而是不确定自己是否真的想从事某个职业：

> “我好像对 AI 产品经理有点兴趣，但不知道是真的喜欢，还是只是觉得这个方向热门。”

传统职业测评容易直接给出标签，普通聊天机器人则可能过度迎合用户的表达。

**可见功能：**

- **想法捕捉：** 从日常对话中识别职业兴趣、尝试意愿和潜在方向，不要求用户先完成一套测评。
- **信号分级：** 区分明确方向、隐含兴趣、证据不足的表达和无关信息。
- **用户确认：** 隐含兴趣先询问是否加入罗盘；证据不足时继续澄清，不替用户创建职业目标。
- **方向管理：** 在职业罗盘中管理已确认方向、来源线索和待验证假设。
- **自主启动：** 用户确认方向后，再决定是否开启探索航程。

**技术亮点：来源可校验的方向信号**

`JsonDirectionSignalDetector` 使用 LLM 做结构化提取，输出：

- `explicitness`：`none / uncertain / implicit / explicit`；
- `label`：识别出的职业方向；
- `source_quote`：来自用户原话的依据；
- `reason` 与 `confidence`：判断原因与置信度；
- `suggested_action`：澄清、询问加入或加入罗盘等后续动作。

系统会校验 `source_quote` 是否真实出现在用户消息中，并检查信号等级与后续动作是否一致。助手自己的回复只能用于消歧，不能成为用户意图的证据。

**核心价值：**

Agent 可以发现用户尚未明确表达的职业兴趣，但不能把自己的推测直接变成用户的职业决定。

**配图建议：** 用户原话 → 结构化方向信号 → 用户确认 → 职业罗盘；把 `source_quote` 高亮为可追溯依据。

## 卡片 5｜核心功能三：职业知识与证据支持

### 不以知识输出维持陪伴，而是在需要探索时提供可靠信息

**用户痛点：**

用户在探索职业方向时，不仅需要理解自己，也需要了解外部职业世界：岗位实际负责什么、需要哪些能力、当前招聘要求如何，以及自己的经历与岗位要求有什么关联。

**可见功能：**

- **岗位信息：** 查看岗位与职业机会。
- **学习资源：** 查找职业准备和能力提升资料。
- **面试资料：** 浏览面试经验与相关题目。
- **个人资料：** 使用简历、作品集和个人笔记支持判断。

Agent 会根据当前任务选择不同信息来源：

| 信息来源 | 回答的问题 |
|---|---|
| Personal Memory | 关于这个用户，哪些经历、偏好和约束值得参考？ |
| Cognitive State | 当前有哪些方向、证据关系和待验证问题？ |
| Private Documents | 用户的简历、作品集和个人资料中写了什么？ |
| Career Knowledge | 外部职业知识和学习资料提供了什么依据？ |
| Jobs | 当前岗位有哪些职责、条件与状态？ |
| Web | 强时效信息是否需要补充核验？ |

**技术亮点：Agent Context & Harness**

- `IntentAwareRetrievalRouter` 根据任务意图生成 `RetrievalPlan`，决定本轮读取哪些上下文、允许哪些工具，以及是否需要最新外部信息。
- `CareerContextCompiler` 把支持策略、记忆、认知状态、检索计划和工具白名单编译成受限上下文。
- `CareerPilotHarness` 控制模型—工具循环的步数、超时、取消、会话锁和事件记录，模型不能自行扩大数据源或工具权限。
- Memory 与 RAG 分工明确：前者提供用户相关上下文，后者提供外部知识与可回源依据。

**核心价值：**

知识不是陪伴感的填充物，而是在职业判断和现实探索确实需要时才进入对话。

**配图建议：** 用户问题进入路由器后，按意图连接不同信息源；倾听场景显示“默认不检索”。

## 卡片 6｜核心功能四：行动管理与现实验证

### 把职业方向变成一段可以持续推进的真实航程

**用户痛点：**

很多职业规划最终停留在收藏岗位、列计划和定目标。用户知道应该做什么，却缺少持续推进的过程；即使完成了一次尝试，结果也很少进入下一轮判断。

**可见功能：**

- **从罗盘开启航程：** 方向确认后，由用户主动开始探索，不自动生成高影响计划。
- **单步聚焦：** 航线保留完整路径，但当前只突出一个主行动，降低多个待办同时出现的压力。
- **状态推进：** 行动从“准备开始”进入“进行中”和“已完成”，完成后形成行动足迹。
- **日历管理：** 支持保存本地日程、设置提醒，并按需同步到飞书日历。
- **未来回信：** 基于当前航程生成多条可能路径，帮助用户思考选择，但不把模拟当作预测。

**技术亮点：可控的外部行动**

- Journey Service 管理职业方向、航程、分支与行动任务之间的关系。
- 外部写操作固定经过“生成预览 → 用户确认 → 执行 → 验证结果”。
- 本地日程与外部日历分开管理；没有可靠双向同步时，不伪装成实时同步。
- 行动、方向和日历是确定性的产品状态，不被混入长期记忆。

**核心价值：**

不只是给用户一份职业规划，而是帮助用户把探索推进到现实生活，并把真实经历带回下一轮判断。

**配图建议：** 罗盘方向 → 航程 → 当前主行动 → 行动足迹；外部日历作为经过确认的可选分支。

## 卡片 7｜核心技术二：Dreaming 认知整理

### 从分散的对话与经历中，发现值得继续验证的认知线索

**用户痛点：**

职业兴趣和自我认知不是在一次对话中形成的。用户可能在不同时间表达过相似兴趣，也可能在实际尝试后推翻原先的判断。

如果 Agent 只保存历史记录，却不整理其中的重复、冲突和变化，就很难形成长期认知。

**可见功能：**

用户可以主动整理最近七天的对话、记忆与个人资料；职业里程碑也可以触发一次有边界的认知整理。系统会形成：

- **阶段回顾：** 汇总近期观察、收获和仍未解决的问题。
- **候选方向：** 从分散表达中发现值得靠近的职业方向。
- **认知假设：** 把重复出现的兴趣、冲突与变化整理为待验证假设。
- **下一小步：** 提出可以继续探索的问题或行动。
- **用户确认：** 候选方向与假设不会直接升级为正式职业决定。

**技术亮点：有证据边界的异步认知**

- `DreamingTriggerPolicy` 识别主动复盘与职业里程碑等触发条件。
- `DreamingSnapshot` 构建带来源的证据快照。
- `DreamingAnalyzer` 生成结构化的假设、阶段回顾与记忆修改提案。
- `CognitiveStore` 管理异步整理任务和候选假设。
- Evidence Validation 检查提案引用的证据是否来自允许的快照范围。

**核心价值：**

让 Agent 从“保存历史信息”走向“基于证据整理认知”，但是否接受某个假设、建立方向或采取行动，最终仍由用户决定。

**配图建议：** 七天证据快照 → 重复/冲突/变化 → 候选假设 → 用户确认；用虚线表示候选不能自动变成结论。

## 卡片 8｜一句话总结与使用建议

### CareerPilot：一个能理解你、记住你，并陪你探索职业方向的 Personal Agent

它的差异化不在某一个独立功能，而在三个横向能力的组合：

- **情绪感知：** 知道什么时候应该倾听，什么时候才适合提供建议。
- **长期记忆：** 记住真正重要的经历和偏好，并允许用户纠正系统的理解。
- **认知与行动协同：** 从日常表达中发现职业线索，通过外部信息和真实行动持续验证。

**推荐使用方式：**

1. 带着一段真实经历开始对话，而不只是问“我适合什么工作”。
2. 允许自己先表达不确定性，不需要马上做出职业决定。
3. 对感兴趣的方向进行确认，再主动开启探索航程。
4. 完成行动后回来反馈，让下一轮判断建立在真实经历上。
5. 定期使用 Dreaming 整理近期变化，检查自己对职业方向的理解是否更新。

**现阶段不适合：**

- 想立刻得到唯一职业答案的人；
- 期待 AI 自动投递、代聊 HR 或替自己完成高风险决定的人；
- 把它当作临床心理诊断或治疗工具的人。

> CareerPilot 不替你选择未来，而是让每一次表达、思考和行动，都成为理解自己的新依据。

**配图建议：** 泊泊位于中心，连接“理解、记忆、探索、行动”四个关键词；底部放产品 Slogan。

## 面试讲解重点

如果用于技术产品经理面试，优先讲清以下三条链路，而不是只说“做了四种聊天模式”“做了长期记忆”或“AI 可以推荐职业”：

| 技术亮点 | 建议讲解主线 |
|---|---|
| 情绪响应控制 | 情绪与诉求信号 → `SupportPolicy` → `ResponseContract` → 约束检索、工具和回答方式 |
| 五类 Memory | 功能分类 → 写入准入 → 状态与版本 → 目的感知召回 → 用户纠正与隐私边界 |
| Direction Signal + Dreaming | 用户原话 → 来源校验 → 待确认方向/假设 → 证据整理 → 用户最终确认 |

一句话项目口径：

> CareerPilot 不是一个“替用户推荐职业”的 Agentic RAG 工具，而是一套把情绪响应、长期记忆、证据检索与现实行动连接起来的个人职业探索 Agent。

### 正文摘要

大多数职业 AI 都在回答“你适合什么”，CareerPilot 想解决的却是另一个问题：当方向还不确定时，如何从真实经历出发，把它一步步探索清楚？

它先判断用户此刻需要倾听、梳理、探索还是行动，再通过长期记忆保留真正重要的经历，用方向信号捕捉尚未说清的兴趣，用职业知识和个人资料补充依据，最后把确认过的方向推进为一段真实航程。Dreaming 会整理跨对话中的重复、冲突与变化，但候选方向、高影响判断和外部动作仍然由用户确认。

如果说普通职业助手更像“答案生成器”，CareerPilot 更像一个有记忆、有情绪感知、能与用户共同形成认知的长期探索搭档。
