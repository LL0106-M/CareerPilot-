# CareerPilot MVP PRD v1.0

> 状态：重构基线草案  
> 产品形态：单前台 Agent + Memory/RAG-native Harness  
> 首期验证周期：4 周

## 1. 产品问题

CareerPilot 面向同时探索 2—3 条职业路径、已有行动意愿但方向尚未收敛的高校高年级学生。
产品不替用户给出唯一职业答案，而是将零散表达转成可验证的职业理解，并通过低风险现实行动持续获得证据。

核心用户任务：

> 当我对职业方向没有把握时，我希望有人记得重要背景、区分事实和猜想，帮助我找到一个可承受的验证动作，并根据真实结果更新判断。

## 2. MVP 要验证的假设

1. 用户愿意在 4 周内持续表达职业相关经历、顾虑和行动结果。
2. 可查看、可纠正的记忆能够提高被理解感，而不会显著增加被监视感。
3. 将方向表达为“假设 + 支持证据 + 反证 + 未知”比直接推荐职业更有帮助。
4. 每次只推进一个 15—30 分钟的验证行动，能够提高现实探索完成率。
5. 有来源的职业知识和岗位信息能够帮助用户行动，但不能替代个人判断。

## 3. 非目标

- 不做自动投递、代聊 HR 或自动报名。
- 不做临床心理诊断与治疗。
- 不使用一次测评生成唯一职业结论。
- 不建设多 Agent 角色团队。
- 不建设完整招聘平台或全量岗位供给池。
- 不在 MVP 中训练或自托管基础模型。

## 4. 核心闭环

```text
表达经历或困扰
→ 识别本轮支持模式和信息需求
→ 召回相关个人记忆、认知状态与职业证据
→ 给出理解、梳理或一个验证动作
→ 用户完成、延期、取消或补充反馈
→ 形成新的 Episode / Evidence
→ 更新候选方向与待验证问题
```

## 5. 支持模式

| 模式 | 用户需要 | 系统行为 | 工具边界 |
|---|---|---|---|
| `listen` | 倾诉与被理解 | 具体慰藉、反映感受、最多一个轻问题 | 禁止检索和行动工具 |
| `organize` | 理清发生了什么 | 区分事实、感受、担忧、猜想和未知 | 可读取 Memory，不对外写入 |
| `explore` | 比较方向和矛盾 | 组织动机、约束、证据和待验证假设 | 可调用受治理 RAG |
| `act` | 推进一个下一步 | 给出完成标准明确的低压力行动 | 外部写入需要确认 |

用户显式选择高于自动判断。出现负面情绪不等于必须停留在 `listen`，但系统不得因为存在可执行任务而自动升级到 `act`。

## 6. P0 用户故事

### 6.1 连续对话

用户能够在后续会话中延续已确认背景。系统必须区分当前会话历史、长期个人记忆和职业知识。

验收：

- Session 在服务重启后可恢复。
- MemOS 不可用时仍可完成当前回复，并明确返回降级状态。
- 当前表达与历史记忆冲突时，以当前表达为准，不静默覆盖。

### 6.2 职业探索

用户能够围绕候选方向查看支持证据、反证、未知和下一步验证方式。

验收：

- 所有 Agent 推断都标记为候选假设，不冒充用户事实。
- 方向至少可以关联支持证据、反证和开放问题。
- 用户能够否认或修正假设。

### 6.3 职业知识检索

用户能够查询职业路径、岗位能力和机会信息，并看到可回源证据。

验收：

- 本地 RAG 优先，资料不足或需要时效性时才联网。
- 回答中的外部事实能够追溯到 `source_uri` 或 URL。
- 无来源或资料不足时明确说明，不补造答案。
- 个人资料与公共知识物理或逻辑隔离。

### 6.4 记忆管理

用户能够知道系统记住了什么，并可纠正或删除。

验收：

- 一次性情绪默认不进入稳定长期记忆。
- 明确事实、长期约束和明确“请记住”可以成为写入候选。
- 人格、能力与职业适配推断只能进入 Cognitive Hypothesis。
- 敏感记忆和冲突覆盖需要确认。

### 6.5 小行动

用户能够把模糊意图转成一个低风险探索动作。

验收：

- 一个行动有目标、预计时长和完成标准。
- 每轮默认最多推荐一个主行动。
- 外部日历、消息和申请操作必须单独确认。
- 完成、延期和取消都能产生现实反馈，而不是只记录“成功”。

## 7. 信息责任边界

| 信息 | 系统 | 示例 |
|---|---|---|
| 当前对话与临时状态 | Working Context | “今天很焦虑” |
| 跨会话用户事实与偏好 | MemOS | 城市约束、明确支持偏好 |
| 方向、猜想与证据关系 | Cognitive State | “可能偏好稳定节奏”及其反证 |
| 通用职业知识 | Governed RAG | 岗位能力模型、招聘规则 |
| 当前外部状态 | Tool/API | 当前是否在招、报名截止时间 |
| 确定性业务状态 | Product State | 任务、收藏、权限、审计 |

## 8. 自主性与权限

| 等级 | 能力 | 默认策略 |
|---|---|---|
| L0 | 对话、梳理 | 自动 |
| L1 | 读取 Memory/RAG | 按模式和范围自动 |
| L2 | 创建内部草稿与 Memory Candidate | 自动产生、可查看 |
| L3 | 写入日历或发送提醒 | 每次确认 |
| L4 | 投递、报名、代发外部消息 | MVP 禁止 |

## 9. 核心指标

北极星指标：四周内完成至少三个现实验证动作，并形成至少一次有证据的方向更新的活跃用户比例。

辅助指标：

- 首周完成首次“表达—梳理—行动”闭环比例；
- 行动完成/延期/取消反馈回收率；
- Memory 候选确认、纠正和删除率；
- RAG 引用覆盖率与无依据回答率；
- 用户对“被理解”和“更清楚下一步”的评分；
- 每轮 Token、延迟、工具失败率和 Memory 召回命中率。

## 10. 发布阶段

### M0：Harness 基线

- 自有模型/工具循环、Session、权限和 Trace。
- 单模型托管 API。
- 现有 MemOS 与 RAG 通过稳定接口接入。

### M1：检索与记忆评估

- 结构化 Intent / Retrieval Plan。
- Memory 召回与写入离线评估集。
- RAG 充分性、引用和时效性评估。

### M2：认知闭环

- Direction、Hypothesis、Evidence 的可编辑视图。
- 行动结果关联证据。
- Consolidation Proposal 审核。

### M3：小规模上线

- 登录与服务端用户隔离。
- 删除、导出、审计和敏感数据控制。
- 12—15 人、4 周封测。

## 11. 上线门槛

- 关键 Harness、Memory、RAG 和权限测试全部通过。
- 不存在跨用户 Memory/RAG 泄漏。
- 外部写操作无法绕过确认。
- 关键职业事实引用可回源。
- 用户可纠正和删除长期记忆。
- 模型或 MemOS 故障时有明确降级路径。

## 12. 待验证决策

意图分类、槽位、任务拆解和能力路由的共创草案见
[用户意图识别与任务拆解 PRD v0.1](./CareerPilot-Intent-and-Task-Decomposition-PRD-v0.1.md)。

- Intent Router 使用规则、模型还是两阶段组合。
- MemOS 的元数据过滤、删除和冲突表达能力是否满足生产要求。
- Cognitive State 在 SQLite 上可支持到什么规模，何时迁移 PostgreSQL。
- RAG 是否需要独立 reranker，以及提升是否超过延迟和成本。
- 每轮主动召回与 Agentic Retrieval 的最佳比例。
